# Maintaining the layer

For whoever changes this bootstrap, or the layer inside a project after `init`. An adopter needs `README.md` only.

## Writing rules for the layer

These are what the layer's own audits paid for; the files follow them and additions should too.

- **A skill or agent description is a trigger, never a summary.** A description that summarizes the workflow makes the agent skip the skill body and work from the summary. Say when to load it and what the user says; keep the how inside.
- **Each mechanic lives in exactly one file.** The lifecycle in `CLAUDE.md` (steps 1-2) and the `lifecycle` skill (steps 3-9), the ladder in `crosscheck`, the browser ritual in `verify-live`. Another file may point, never restate.
- **A count or a site list rots.** Write the grep that finds the sites.
- **Delete what is true but dead**: a status, an instruction for a change already applied, an alternative nothing uses, a paragraph another loaded file already says. A fact-check alone leaves it standing; `drift` reports dead text too.
- **Where text lives**: a prohibition that must be known before any file is read stays in `CLAUDE.md`; one about code in files a rule covers lives in that rule alone. Point rule globs at what the rule describes, not at everything it governs, and measure bytes-of-rules-per-file-read.
- **Measure in bytes, never in lines.** `CLAUDE.md` loads in full on every session, so its cost is paid by every conversation; long lines grow a file while its line count shrinks. The 32 KB budget is the layer's own choice, not a tool limit.
- **Form matches the failure.** A prohibition the model keeps rationalizing past gets a hook, not a stronger adjective; a step it skips gets "name each skill and agent the task ran" so the skip is visible.
- **Reviewers get "deliberate - here is why", never "do not flag".** A no-flag list inherits the implementer's blind spots.
- **Every agent pins a model and an effort.** Inheriting the session's means the review gets quietly cheaper exactly when the session is running cheap - which is when it is needed most. The one stated exception is `maintain-ai-layer`, which runs its agents on Sonnet; its standing rules say why.
- **An instruction that can be verified by a command is verified by the command, not believed.** Write the check next to the claim.
- **Agents never see images.** Whatever a screenshot showed is transcribed into the Brief that every agent prompt carries.
- **Every file of the layer is in one language**, trigger phrases in descriptions included - the model matches a request written in another language by meaning. The reply follows the user's language by the Working Principles rule, which names no language itself.
- **Plain hyphens everywhere.** The guard refuses a dash in any file under the project, and the rule has no off-switch.

## Facts about Claude Code this layer relies on

- A hook script is read on every call, so an edit to it applies at once; a changed registration in `settings.json` is not guaranteed to reach a running session. Agents and skills in an existing `.claude/agents` / `.claude/skills` folder are picked up live, but a session that started before the folder existed does not see it - which is why the install ends with a restart.
- `PreToolUse`: exit 2 + stderr blocks the call and shows the reason to the model. `SessionStart`: `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"..."}}` on stdout injects context. `Stop`: `{"decision":"block","reason":"..."}`; `stop_hook_active: true` means it already fired this turn - never block again.
- A subagent's own tool call carries the parent session's `session_id` plus its `agent_type`, which is what the guard's write fence reads; a payload without it fails open.
- The public hooks reference documents no output fields for `PreCompact` or `PostCompact`. Send `systemMessage` alongside whatever else you try, so a pointer is not lost to an unsupported channel.
- The browser tools record nothing before their own first call: `read_console_messages` and `read_network_requests` answer "none found" for everything that happened earlier, which is indistinguishable from a clean run. Arm them right after the marker navigation, before navigating to the app.
- `${CLAUDE_PROJECT_DIR}` in a hook command resolves per tree; `settings.local.json` is not carried into a new worktree.
- A deny in `permissions` outranks every allow at every scope and matches the raw command string only.
- `CLAUDE.md` is read up to 4 MiB; the 32 KB budget is the layer's own. `MEMORY.md` is read up to 200 lines / 25 KB.
- The Bash tool eats backslashes in its arguments; a regex or path with backslashes is built in a script file, or with `String.fromCharCode`. The working directory persists across calls, so a `cd` in a chain retargets every later relative path.
- The Grep tool skips gitignored paths unless the folder is passed as its path, and misses files when its `path` is `.claude` itself - ripgrep misapplies the `.claude/*` ignore-plus-negation lines at that root, so a zero- or low-hit answer there proves nothing. Search `.claude` from the repo root with `glob: '.claude/**'`, or pass a subfolder.
- A path-scoped rule loads in full when the Read tool opens a matching file, once per context - after `/compact` it loads again on the next matching Read. Glob, Grep, Write and Edit load nothing, a Bash command that reads the file (`head`) does, a subagent's Read loads into that subagent only, and a rule whose own file was already Read is not injected again. Only the Read trigger is documented; the rest is observed. A rules file without `paths:` loads on every session. The loader expands every brace group, strips a trailing `/**` and matches with gitignore semantics: a glob with an inner slash is anchored at the root, a slash-less one (a folder glob such as `nginx/**` included, once stripped) matches at any depth; there is no negation.

## The guard's known gaps

`template/.claude/hooks/README.md` points here. A bypass nobody would type by accident is recorded here, not closed with more guard code; a realistic slip, or a retry after a refusal, is a defect to fix in `guard.mjs`.

- Refused though harmless (fail-closed): what the as-written view makes of a comment - a quoted string after a `# it's` comment read as a command, trailing comment words read as arguments (`rm <SRC_DIR>/a.ts # orphaned` counts two paths, `cp a b # backup`), a `;`, `|` or `&` in a comment before a `cd` word; a `cd` line inside a heredoc body a shell reads, behind an unquoted `cmd /c`, after a `;` in a backtick body, after a `case` pattern's `)` inside a subshell, or after a line continuation, a PowerShell hashtable key named `cd`, and `echo x | cd`; a mover target whose own name holds a comma; one path spelled relative and absolute in one call (two deletes); a copy or `find -maxdepth 1 -delete` into an ancestor directory of the project, and a glob or bracketed name directly under one; a `\\?\UNC\` path; a target held in a leading-literal variable not named as scratch, beside a sibling value holding shell syntax or a quoted `~`, a Bash-managed name, or a comment, heredoc or `eval` in the command (`U="...?a=1&b=2"; O=/tmp/o; curl "$U" -o "$O"`, `O=/tmp/o.txt; echo hi > "$O" # note` - name it `$S`); a `git grep` word that only looks like `-O` (`git grep -eOrder`, `-e "-O"`), a `--output` search pattern or path (`git log -S "--output"`), and `--output=<scratch path>`; search text holding `bash -c '...'` or `sh -c`; `[[ "$a" > "b" ]]`; a heredoc whose body a shell reads, or an unquoted one whose `$(...)` or backticks name a banned form; a `node -e` / `python -c` / `perl -e` one-liner, or a script fed to an interpreter on stdin, whose code quotes a git write verb as text; a `node` / `python` call with `-e`, `-r` or `-c` among its script's arguments that quotes one.
- The stdin and arithmetic checks. Refused though harmless: a script an interpreter reads on stdin that writes to a computed path, scratch included (`os.path.join(os.environ['TEMP'], ...)` - write it to a scratch file and run it by path); a write API or a git write verb anywhere else in a command that also feeds an interpreter or a shell on stdin; an arithmetic command `(( n > 0 ))`, which Bash may also parse as nested subshells. Passes though it writes: a `$((` opened inside quotes, which blanks everything up to the next `))` from every check but the `cd` one; a stdin script fed in a shape the check does not read (`<<EOF node` with the redirect first, `node /dev/stdin`, `node <(...)`, `python -m code`, an interpreter flag whose value it does not know).
- Passes though it writes, for a fenced agent: whatever a process it starts writes, and a `Write` to an absolute path outside the project, such as another worktree.
- Passes though it writes: a formatter not in `formatterWrites` (add its form there for such a project), and, by decision, a build tool's formatting task (`./gradlew spotlessApply`, `mvn spotless:apply`) and a fixing package script (`npm run lint:fix`, `npm run format`) - the project's own scripts; a release tool not in `RELEASE_TOOL` (`np`, `yarn publish`); git that writes files (`format-patch` without `--stdout`, `archive -o`, `bundle create`); a download into the cwd (`curl -O`, `wget` without `-O`); `ln`, `touch`, `tar -x -C`, `unzip -d`, a `w` or `e` in a sed script file (`sed -f`), PowerShell's `Export-Csv`, `Expand-Archive` and `Start-Transcript`; a shell-out inside a one-liner (`execSync('rm ...')`, `os.system`, `subprocess`) and `perl -e` / `ruby -e` / `deno eval` file writes; a git verb from a variable or substitution (`git $v`, `git $(echo commit)`).
- Passes though it writes: a target spelled as any other variable plus a path holding `/tmp/`, `Temp` or `scratchpad` (`> $ROOT/<SRC_DIR>/Temp/x`) - only the listed scratch variables should pass, but the check reads the substring; a listed scratch name set to a project path by an assignment that is not a leading literal (`true; S=<SRC_DIR>; rm -r $S`, `S=$PWD/<SRC_DIR>; cp a "$S/x"`, and `A=$HOME; S=<SRC_DIR>; ...`, where the non-literal first assignment ends the leading scan), or rebound to one after a scratch leading value (`S=<scratch>; cp a "$S/x"; S=<SRC_DIR>; rm -r "$S"`); a quoted `~` path, which Bash keeps literal and writes as `./~/...` inside the project while the check reads a home path - `cp a "~/AppData/Local/Temp/x"`; a leading-literal name rebound by `coproc X`, `wait -p X`, `printf -v "X"` / `-vX`, or a shell-managed `DIRSTACK` / `COLUMNS`; a `~` after a space inside a quoted leading value (`X="/tmp/a ~/AppData/Local/Temp/x"; cp a $X`); `IFS` splitting a scratch value, which then passes by its name (`IFS=:; S="/tmp/a:<SRC_DIR>"; rm -r $S`); the substitution's quote tracking, which misreads a single quote inside `"$(...)"` and after an escaped backslash (`"\\"`).
- Passes though it writes: an `Edit` / `Write` of any path under a `.git`; a `cd` behind `eval`, `builtin`, a backslash or quotes (`\cd`, `"cd"`), PowerShell's `iex "cd ..."` or a module-qualified `Set-Location`; a git `-O` the read-git check never sees as one (`git grep $'-Ocat'`, `xargs git grep -Ocat`); cmd switches glued to the verb (`cmd /c rd/s/q <dir>`); an escaped apostrophe in ANSI-C `$'...'` quoting, a `${` inside a heredoc body, a PowerShell here-string that holds a `"`, and a doubled PowerShell backtick before `#`; a bash brace range or list that the split at braces hides (`rm -rf /d/code/my-ap{o..q}`); an in-tree marker path behind a cwd spelling the check does not rewrite (`$PWD.Path/tmp/x`); a verb assembled inside a one-liner (`'git ' + 'commit'`, `` `git ${v}` ``); `& git @('add','-A')` and `Start-Process git -ArgumentList @(...)`; git behind a launcher `GIT_LAUNCHER` does not list; `-i` after `sed`'s script (`sed 's,a,b,' -i f`) or after a flag holding a comma (`--expression=s,a,b,`, `perl -Mx=a,b -pi`).
