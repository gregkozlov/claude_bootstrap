# Hooks

Four dependency-free Claude Code hooks (Node 18+, no packages), every one registered in `.claude/settings.json`, so a tree has them once its `.claude` folder exists. A personal layer inside a `.claude/` folder the team tracks registers them in the personal `.claude/settings.local.json` instead (`INSTALL.md`, step 8), and a personal layer never follows into a new worktree by itself.

| Hook | Event | Registered in | What it does |
| --- | --- | --- | --- |
| `guard.mjs` | `PreToolUse` on `Bash`, `PowerShell`, `Edit`, `Write`, `MultiEdit`, `NotebookEdit` | `.claude/settings.json` (beside the deny list) | Refuses a tool call CLAUDE.md forbids outright, before it runs |
| `upkeep-nudge.mjs` | `SessionStart` (startup, clear) | `.claude/settings.json` | Says so when the `maintain-ai-layer` pass is 30 days overdue, or never ran in this tree |
| `compact-pointer.mjs` | `SessionStart` (startup, resume, clear, compact) + `PreCompact` + `PostCompact` | `.claude/settings.json` | Names this session's artifact folder. `SessionStart` hands the model the session id prefix and the folder it has, or the name to open one under (`additionalContext`), and on `compact` where to resume from; `PreCompact` prints one plain-text line on stdout - `Keep in the summary: this session's notes are in <folder> - read its task file before continuing.` - which Claude Code adds to the instructions for the compaction summary; `PostCompact` names the folder to the user (`systemMessage` - the harness rejects `hookSpecificOutput` on `PostCompact`). Both compaction events stay silent when the session has no folder |
| `stop-check.mjs` | `SessionStart` (startup, resume, clear, compact; timeout 30) + `Stop` (timeout 180) | `.claude/settings.json` | Runs `<CHECK_COMMAND>` at the end of a turn when the tree moved off the session's start state, and blocks once on a failure |

Start Claude Code at the repository root. Started in a subfolder it does not read the root `.claude/settings.json`: no hook and no deny entry is live, though `CLAUDE.md` still loads. `/hooks` shows what is registered.

After changing a hook registration in a settings file, start a new session: a running one is not guaranteed to pick it up.

The hooks read payload fields Claude Code does not promise to keep (`session_id`, `agent_type`, `stop_hook_active`, `hook_event_name`). A renamed field fails silently - check the payload before trusting the Stop hook or the write fence.

**No hook picks up another session's handoff.** Several sessions can run in the same tree at once, and a handoff belongs to one task, not to whoever starts next. The handoff lives in the session's own folder under `.claude/sessions/` and is handed over by hand - the `precompact` skill ends by printing the sentence to open the next session with. Do not add such a hook. `compact-pointer.mjs` is not that hook: it names only the folder of the session it fires in, and never reads another one.

## Facts about the hook protocol this layer relies on

- A hook reads one JSON payload on stdin: `hook_event_name`, `session_id`, `cwd`, plus `tool_name` / `tool_input` (and `tool_response` after the call) for a tool event, `source` for `SessionStart`, `trigger` (`manual` or `auto`) for `PreCompact`, `stop_hook_active` for `Stop`. `CLAUDE_PROJECT_DIR` is set in every hook's environment, and `${CLAUDE_PROJECT_DIR}` in a registered command resolves per tree.
- `PreToolUse`: exit 2 with the reason on stderr blocks the call and shows the reason to the model; exit 0 allows it.
- A subagent's own tool call carries the **parent** session's `session_id` plus its `agent_id` and `agent_type` (measured) - which is what the guard's write fence reads.
- `SessionStart`: `source` is `startup`, `resume`, `clear` or `compact`; stdout JSON `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"..."}}` injects text into the session's context. A `startup` can keep a session id that already has state - the id survives a restart (measured).
- `Stop`: stdout JSON `{"decision":"block","reason":"..."}` makes the model continue with the reason; `systemMessage` reaches the user only, never the model. There is no third channel - a Stop hook cannot tell the model anything without blocking. `stop_hook_active: true` means the Stop already fired once for this turn - never block again then, or the session loops. A hook still running at its registered `timeout` is killed and writes nothing.
- `PreCompact`: plain text on stdout is added to the instructions for the compaction summary, which is how `compact-pointer.mjs` gets the folder into the summary itself.
- `PostCompact`: `systemMessage` reaches the user. `PostCompact` rejects `hookSpecificOutput` (measured at a real `/compact`), so `compact-pointer.mjs` sends `systemMessage` alone there and hands the model its pointer through the `SessionStart` whose `source` is `compact`.

## guard.mjs - the PreToolUse guard

Deterministic, milliseconds, no state. Exit 2 with the reason on stderr blocks the call; exit 0 allows it; input it cannot parse is allowed (the deny list in `settings.json` and the rules still stand behind it). It is a best-effort net for a well-meaning model, not a security boundary.

- **Git.** `git` is judged where a shell runs it, on the words it receives (quotes and escapes resolved, so `git -C "D:/Work Projects/x" reset` and `git -c "user.email=a b" commit` count): at command position after leading keywords, assignments and wrappers (`env`, `sudo`, `time`, `nohup`, an unquoted `cmd /c`) are stripped, behind a runner (`npx`, `uv run`), after a launcher (`xargs`, `find -exec`, `wsl`, `Start-Process`), inside `$(...)`, backticks and a `bash -c` / `cmd /c` / `pwsh -Command` / `iex` body, as `git.exe` or a quoted path to the binary; and anywhere inside code an interpreter runs (`node -e`, `python -c`, `perl -e`, `ruby -e`, `eval`, a script fed on stdin or piped into `bash`), argv arrays included (`["git", "stash"]`, escaped quotes too). Git words in an argument are text (`echo "never git push"`, `npm test -- -t 'git checkout flow'`). Refused: the verbs in `GIT_WRITE_VERBS` (`send-email` included), the writing subcommands in `GIT_WRITE_SUBCOMMANDS` (`subtree` and `lfs push` / `migrate` included - `lfs pull`, `fetch` and `install` pass), `fetch` with a refspec whose destination is not under `refs/remotes/` (`git fetch . HEAD:main`), `apply` without `--check` / `--stat` / `--numstat` / `--summary`, `merge-file` without `-p` / `--stdout`, a `config` write, `symbolic-ref` with two operands, and `branch` with a delete, move, copy, force or upstream flag. `stash` is judged by an allow list instead: only `git stash list` and `git stash show` pass, since a bare `git stash -m <msg>` pushes and its first non-flag token is the message; the `settings.json` deny entries name the same writing forms (bare `git stash`, `git stash -...` and each writing subcommand). `git tag --list` stays refused by design. A text search (`grep`, `rg`, `findstr`, `Select-String`) and a read verb's quoted argument (`git log -S "git add"`) are text, unless the segment runs a `$(...)`; so is the pattern of a search behind a launcher (`git ls-files | xargs grep -n "git commit"`, `find . -exec grep -l "git push" {} +`), while git itself behind one (`xargs git add`) stays git.
- **Release tools** that commit, tag or push through git: `npm` / `pnpm` / `yarn version` unless `--no-git-tag-version` (bare `npm version` only lists), `release-it`, `standard-version`, `commit-and-tag-version` and `semantic-release` unless `--dry-run`, `lerna version` / `publish`, and `changeset publish` / `tag` - directly or through `npx`, `pnpm exec` / `dlx`, `yarn` or `bunx`. `changeset version` only rewrites files and passes.
- **`gh`** is refused when it creates, merges, edits, closes, reopens, locks, transfers or deletes anything, checks out a pull request, runs, cancels or toggles a workflow or run, or sets a secret, variable or label, and for `gh api` with a non-GET method or, with none given, a field flag - except a `graphql` query with no `mutation`. Like git, `gh` and the in-place tools under Shell writes are judged where a shell runs them: a quoted argument of another command is text (`echo "next: gh pr create"`, `npm test -- -t "gh release create"`, `echo "use sed -i to fix"`). The quoted text is still read where it can run or is the tool's own - `gh`, `sed`, `perl` and `awk` heading the command, an interpreter's code, a launcher (`xargs`, `Start-Process`) that starts no search, a bare assignment (`C="gh pr create"`), a segment with a `$(...)`, and any command that feeds a script to an interpreter or shell on stdin or pipes a string into `iex`.
- **Read git that runs or writes**, for anyone: `git grep -O<cmd>` / `--open-files-in-pager` (clustered as `-nOcat` or abbreviated as `--op=` too) starts a program and any verb's `--output[=]<file>` writes one, judged on the words git receives (quotes and escapes resolved, so `-"O"cat` counts). The read-only git prefixes in `settings.json` (`git diff:*`, `git log:*`, `git show:*`) would approve `--output` with no prompt.
- **Interpreters and nested shells.** A one-liner (`node -e` / `-p`, `python -c`, `py -c`, `pwsh -Command`, `iex`) is refused when a write API in it (`writeFileSync`, `rmSync`, `open` with a write mode, pathlib's `Path('x').write_text` / `write_bytes` on its receiver; `copyFileSync` / `renameSync` / `shutil.copy` on the destination, a rename on its source too - `rename` only as a file API, bare or on `os.`, `fs.`, `Path(...).` or `require(...).`, so pandas' `df.rename(columns=...)` passes) names anything but a literal scratch path - a computed path cannot be proven scratch; the same holds for a script an interpreter reads on stdin (`python - <<'EOF'`, `node <<EOF`, `... | node`), judged over the whole command - its git calls too; a shell reading stdin (`... | bash`, `bash -s`) counts as such an interpreter. A `.NET` write (`[IO.File]::WriteAllText`, `Copy` / `Move` / `Replace`, `[IO.Directory]::Delete`) is judged the same in any command. The string body of `bash -c`, `sh -c`, `cmd /c`, `pwsh -Command` and `iex`, every `$(...)` outside single quotes and every bash backtick pair is checked again as a command line, read with the outer tool's own quoting.
- **Working directory.** `cd`, `chdir`, `pushd`, `popd`, `Set-Location`, `sl`, `Push-Location` and `Pop-Location` are refused at the head of any top-level command outside a heredoc body no shell reads, because the cwd persists across calls and into another worktree. Only a Bash subshell - `( ... )`, `$(...)`, a `bash -c` body - may change it; PowerShell has no subshell, so its parentheses and script blocks do not count, and its `cd..` / `cd\` shortcuts are refused too. The refusal names the retry form for its shell: the subshell in Bash, absolute paths, `git -C` or `npm --prefix` in PowerShell. This and every other command check judge each command twice - as written and with its shell comments blanked, a `bash -c` / `pwsh -Command` body likewise with its own shell - and refuse if either view does, so an apostrophe in `# it's` cannot open a quote that hides the lines after it, while the blanked view can only add a refusal, never lift one. Blanking takes a `#` that is a whole word (after unescaped whitespace or `;&|`, outside `${...}`) to the line end or, inside a backtick body, to its closing backtick, and PowerShell's `<# ... #>` only at a word start.
- **Movers.** `cp`, `mv`, `install`, `dd`, `truncate`, `patch`, `shred`, `rsync`, `robocopy`, `xcopy`, `ed`, `ex`, `rm`, `tee`, `unlink`, cmd's `copy`, `move`, `del`, `erase`, `rd` and `rmdir`, the PowerShell `*-Item` cmdlets and their aliases, `Clear-Content` and its alias `clc`, `Tee-Object`, `Set-Content`, `Add-Content`, `Out-File` (and, under the PowerShell tool only, their aliases `sc` / `ac`), and the output flags of the downloaders and of `sort` (`curl -o`, `wget -O`, `-OutFile`, `sort -o`) are judged at command position, after leading keywords, assignments, `$null =`, `[void]`, wrappers and an unquoted `cmd /c` are stripped, with commands split at `;`, `|`, `&`, newlines, parentheses and braces outside quotes. A mover is refused when a target is not provably scratch or outside the project (a relative path never is), when a target is a variable the guard cannot resolve (only the scratch variables under Shell writes resolve, plus, in Bash, a name a leading statement sets to a literal - `O="/tmp/out"; cp a "$O/b"` is judged as `cp a "/tmp/out/b"` - unless the rest of the command assigns, loops over, reads into or unsets it, or any leading value holds shell syntax or a quoted leading `~`, or any leading name is one Bash sets itself (`_`, `IFS`, `PWD`, `RANDOM`), or the command holds a comment, a heredoc, `eval` or other grammar the scan does not follow; a skipped substitution, a rebound name and a `${S%/}` form each leave a scratch name whose leading value is not scratch unresolved, so `S=<SRC_DIR>; ... # x` is refused rather than passed by name; and a name set from `mktemp` anywhere in the command - `T=$(mktemp); npm ls > $T`, or in PowerShell from `New-TemporaryFile` / `[IO.Path]::GetTempFileName()` - unless the command binds it any other way or the template or `-p` directory lies in the project), or, unless it is `tee`, `Tee-Object`, a downloader or `sort`, when it has no target. A PowerShell parameter's value is not a path (`-ErrorAction`, `-ItemType`) while `-Path` / `-Destination` are, and a copier's only write is its destination. A comma-joined target (`Remove-Item a,b`, or `a, b` over two words in PowerShell) is split and every part judged on its own. `find ... -delete` / `-exec rm` is refused unless every root is scratch, and a mover behind `xargs` always.
- **Inside the project** `MOVER_EXEMPT` at the top of the script passes any mover: anything under `node_modules`, judged after `..` is resolved, and the compile probe `<SRC_DIR>/__hunt_probe*.ts`, which a review agent is required to delete and has no other way to; a project's own exemptions go into `MOVER_EXEMPT`. No other copy or move into the project passes, whatever its flags.
- **The delete grant.** A delete (`rm` / `del` / `Remove-Item` / `unlink`) of a file the change itself orphaned passes with no recursive flag (`-r`, `-R`, `-rf`, PowerShell `-Recurse` or any `-Re` prefix, cmd `/s` or `//s`, clustered as `/s/q` too), never a glob (`*`, `?`, or a `[...]` name that does not exist as written - `rm "app/blog/[slug]/page.tsx"` on an existing file is that one file), never a `del` of a directory (it empties it), and **one project path per call**, counted across a chain (`rm a; rm b` is two) - the compile probe counts toward that cap, a path under `node_modules` does not - and never on a path matching `PROTECTED_PATHS`, `.git`, `.claude/hooks/**` or `.claude/settings*.json`, each judged after `..` is resolved.
- **Shell writes.** Refused when the command edits a file in place (`sed -i`, `perl -i`, `ruby -i`, `awk -i inplace`, `yq -i`; `prettier --write` / `-w`, `eslint --fix` and `stylelint --fix`, bare, from `node_modules/.bin` or through `npx`, `bunx`, `bun x`, `pnpm`, `yarn` or `npm exec`; `lint --fix` through `npm run`, `pnpm`, `yarn` or `bun`, `biome --write`; `black`, `isort`, `ruff format` and `ruff --fix`, `gofmt -w`, `goimports -w`, `go fmt`, `golangci-lint run --fix` and `golangci-lint fmt`, `dotnet format`, `dotnet csharpier`, `cargo fmt`, `rustfmt` on files, `ktlint -F`, `google-java-format -i`, `clang-format -i` and `rubocop -a` / `-A`, directly or through `python -m`, `uv run`, `uvx`, `poetry run` or `npx` - a check flag such as `--check`, `--check-only`, `--diff` or `--verify-no-changes` only reads, as do `goimports -l` / `-d` and a linter run with no `--fix`, and a project's own task such as `./gradlew spotlessApply`, `make fmt` or a format script run through `npm run` passes. A formatter this project runs that is not on the list: add its form to `formatterWrites` in `guard.mjs`, with a case in `tests/guard-shell-test.mjs`.) - with no scratch exemption, since the target of an in-place edit cannot be told from the rest of the command - or redirects into a file (`>`, `>>`, `2>`, `>|`, `>&`, `&>`, a quoted or escaped target too, read whole with its blanks, so a project root with a space in its path is judged like any other; `2>&1` names no file, and `tee` is a mover) whose target is not provably scratch: `/dev/null`, `$null`, `NUL`, an absolute path outside the project (an ancestor of it, or a glob in one, counts as inside; a `\\?\` prefix is ignored), a `~/` path containing `/tmp/`, `Temp` or `scratchpad`, or a variable naming one (`$S`, `$TMP`, `$TEMP`, `$SCRATCH`, `$TMPDIR`, `$M`, `$env:temp` / `$env:tmp` or `${env:temp}`, `%temp%` / `%tmp%`, a name set from `mktemp` or `New-TemporaryFile`). `sed`'s `w` / `W` command and `s///w` flag are judged the same, `/dev/stdout` passing; its `e` command and `s///e` flag run a shell command and are always refused. A scratch variable is read as written unless a leading Bash statement sets it to a literal (see Movers); any other path is judged after `..` is resolved, and `$PWD`, `%CD%` or `$(pwd)` name the project, so `./tmp/x` is refused like any other relative path or unknown variable - repo files are changed with `Edit` / `Write`. Every other quoted span is data, so a `>` inside a search pattern is not a redirect. A heredoc body no shell reads (`cat > /tmp/x <<'EOF'`, `python3 - <<'EOF'`, `psql <<'SQL'`) is not judged as commands, so its `>`, `cd` or `git push` lines pass; one a shell reads (`bash <<EOF`, or any command naming `bash`, `sh`, `eval` or `source`) is, and an unquoted heredoc's `$(...)` and backticks run and are judged.
- **`Edit` / `Write` / `MultiEdit` / `NotebookEdit`**: refused for a path matching `PROTECTED_PATHS` - regex sources at the top of the script, filled at install from `<GENERATED_PATHS>` (`INSTALL.md`; a placeholder left unfilled reads as an empty list, and a misfilled one - not a JSON array of regex sources - is named in one stderr line and reads as empty too, every other check staying live) and tested against the tool's `file_path` with every backslash turned into `/`, case-insensitively on Windows and macOS (an empty list protects nothing); and, for any file inside the project, when a written **line** contains an en dash (U+2013) or an em dash (U+2014) - every other dash-like character (minus sign, non-breaking hyphen, figure dash) passes. The one exception is a line that spells the punctuation rule itself (contains "plain hyphen"), and it is per line rather than per payload, so one exempt sentence cannot carry a whole file's dashes past the check. Files outside the project (memory, scratchpad) are not dash-checked.
- **The write fence.** When the payload names the agent, an `Edit` / `Write` / `NotebookEdit` or a mover target inside the project is refused outside that agent's paths (`FENCED_AGENTS`): `hunt` may touch only `<SRC_DIR>/__hunt_probe*.ts` - `node_modules` included. The fence narrows, it lifts nothing: a mover or redirect into an allowed path is still judged by every other check, and a delete still goes one path at a time. A project's own writer agent with a narrow job gets an entry of its own - an `allowed` regex over the project-relative path and the `what` its refusal names. A payload without `agent_type` fails open - the agent's prompt still carries the rule.

The deny list in `settings.json` stays as the first backstop: a deny outranks every allow at every scope, and it needs no script to run. It matches the raw command string, so it catches fewer shapes than the guard does: `git -C <path> commit`, a quoted path to the binary and a git call inside an interpreter one-liner slip past it, and the guard catches those over the whole command - keep both. An allow or deny entry's `*` compiles to `.*` under the `s` flag, anchored at both ends (measured on Claude Code 2.1.296), so it spans spaces, slashes and extra arguments. The one path wildcard in the shipped allow list is the probe compile, `npx tsc -p * --noEmit --tsBuildInfoFile *`, which also approves a `--tsBuildInfoFile` or `--generateTrace` aimed into the project.

**Known gaps.** A bypass nobody would type by accident is recorded, not closed with more guard code; a realistic slip, or a retry after a refusal, is a defect to fix. The writes the guard lets through are listed in `MAINTAINERS.md` in the bootstrap folder this layer was installed from; the harmless commands it refuses are below.

**Refused though harmless - known.** `guard.mjs` fails closed: where it cannot tell a harmless command from a banned one, it refuses. The cases below are known, not defects to report, and each has a way round.

- **A shell comment in the command**: a quoted string after a `# it's` comment is read as a command, trailing comment words as arguments (`rm <SRC_DIR>/a.ts # orphaned` counts two paths, `cp a b # backup` copies onto `backup`), and a `;`, `|` or `&` in a comment before a `cd` word as a `cd`. Drop the comment and say it in the reply.
- **A `cd` word the guard cannot place**: a `cd` line inside a heredoc body a shell reads, behind an unquoted `cmd /c`, after a `;` in a backtick body, after a `case` pattern's `)` inside a subshell or after a line continuation; a PowerShell hashtable key named `cd`; `echo x | cd`. Use absolute paths or a Bash subshell, `(cd dir && cmd)`; rename the key.
- **Paths**: a move target whose own name holds a comma; one path spelled relative and absolute in one call, read as two deletes; a copy or a `find -maxdepth 1 -delete` into a folder above the project, and a glob, or a bracketed name that does not exist as written, directly under one; a bracketed name escaped instead of quoted (`rm app/\[slug\]/page.tsx`); a `\\?\UNC\` path. Spell a path once, in one form, and quote a bracketed name; a step in a folder above the project is the owner's to run.
- **A target held in a variable**: a variable a leading statement sets to a literal and that is not named as scratch, beside a sibling value holding shell syntax or a quoted `~`, a Bash-managed name, or a comment, heredoc or `eval` in the command (`U="...?a=1&b=2"; O=/tmp/o; curl "$U" -o "$O"`, `O=/tmp/o.txt; echo hi > "$O" # note`). Name the scratch variable `$S`, or write the path out.
- **Text that only looks like a banned form**: a `git grep` word that looks like `-O` (`git grep -eOrder`, `-e "-O"`), a `--output` search pattern or path (`git log -S "--output"`) and `--output=<scratch path>`; search text holding `bash -c '...'` or `sh -c`; `[[ "$a" > "b" ]]`; a heredoc whose body a shell reads, or an unquoted one whose `$(...)` or backticks name a banned form; a `node -e` / `python -c` / `perl -e` one-liner, or a script fed to an interpreter on stdin, whose code quotes a git write verb as text; a `node` / `python` call with `-e`, `-r` or `-c` among its script's arguments that quotes one; `gh` or in-place tool words left unquoted in another command's arguments (`echo use sed -i`), or quoted in `gh`'s own (`gh search issues "gh pr create"`). Search with the Grep tool; quote the text; put the code in a scratch file and run it by path.
- **A script on stdin, and arithmetic**: a script an interpreter reads on stdin that writes to a computed path, scratch included (`os.path.join(os.environ['TEMP'], ...)`); a write API, a git write verb, or quoted `gh` or in-place tool words anywhere else in a command that also feeds an interpreter or a shell on stdin; an arithmetic command `(( n > 0 ))`, which Bash may also parse as nested subshells. Write the script to a scratch file and run it by path; test with `[ "$n" -gt 0 ]`.

**Switching a rule off.** A rule is one `CLAUDE.md` section plus its checks here. Switch both off together, rewrite the section to the new policy (the agents read it), run the self-tests, and delete the cases that expect the old refusal.

- **Never commit** (`CLAUDE.md`, "Version Control"). In `guard.mjs`, trim `GIT_WRITE_VERBS` and `GIT_WRITE_SUBCOMMANDS` to the verbs that stay refused - to allow every git write, empty both and make `gitCallWrites` return `false`. Publishing has its own checks: `ghWrites` (`gh`, by `GH_MUTATING`) and `releaseWrites` (`npm version` and the tools in `RELEASE_TOOL`). In `settings.json`, delete the matching `Bash(git ...)` and `PowerShell(git ...)` entries of `permissions.deny`, or the deny list keeps refusing what the guard now allows.
- **No `cd`** (`CLAUDE.md`, "Shell and file edits"). In `guard.mjs`, narrow the `CHDIR` pattern, or delete the refusal that tests it; no deny entry backs it.
- **Plain hyphens** have no off-switch: the dash check and the Punctuation section stay.

**Self-test** after any change to the regexes, from the project root:

```bash
node .claude/hooks/tests/guard-test.mjs
node .claude/hooks/tests/guard-shell-test.mjs
```

Each suite ends with `N passed, 0 failed`; the tests set `CLAUDE_PROJECT_DIR` themselves. The payloads are built in JavaScript on purpose - a Windows path or a dash typed into a shell argument gets mangled before the guard sees it. Add a case per `PROTECTED_PATHS` pattern (the two commented lines in `guard-test.mjs`); the matching itself, case folding and a misfilled list are tested on two temp copies of the guard with a known list, whatever this project's list is.

## upkeep-nudge.mjs - the upkeep reminder

Reads the date in `.claude/.last-maintain` (committed with the layer in team mode, per machine in a personal mode; one `YYYY-MM-DD` line, written by `maintain-ai-layer` after a `deep` or `init` run) and, when it is 30 days old or more, more than a day ahead, missing or unreadable, injects a line telling the model to tell the user once that `/maintain-ai-layer` is due - never to start it. Silent in a linked worktree (the nearest `.git` is a file): the pass runs in the main tree, and a second tree would be told so on every session. It reports and never blocks. Self-test: `node .claude/hooks/tests/upkeep-nudge-test.mjs`.

## stop-check.mjs - the Stop hook

Runs `<CHECK_COMMAND>` (the `CHECK` constant at the top of the script, the one verification call from `CLAUDE.md`, run through the shell) at the end of a turn when the tree moved off the session's start state, and blocks the turn on a failure. One file, two events, both registered beside the other hooks, so a new worktree has the hook once its `.claude` folder exists. The always-on summary lives in `CLAUDE.md` under `## Commands`.

- **`SessionStart`** (`startup`, `resume`, `clear`, `compact`; timeout 30) stores the current tree key as this session's baseline under `%LOCALAPPDATA%/claude-stop-check/` (or `$XDG_CACHE_HOME`, or `~/.cache`), keyed by the repo root and the session id - **only when that session has no baseline yet**. `/compact` and `resume` keep the session id and fire `SessionStart` again; re-baselining there would pass the session's own edits. `fork` is absent from the matcher: a fork's new id would baseline the parent's already-modified tree. State files untouched for 15 days are pruned at session start.
- **`Stop`** (timeout 180) exits at once when `stop_hook_active` is set. Otherwise it computes the tree key and skips the check only when the key is defined **and** equals the baseline, the key of the last passing run, or the key of the last failure it already blocked on. A missing baseline or an undefined key (any git error) counts as changed. With no key the check runs on every Stop, and the failure's own output (its tail, digits masked) keys the block instead: the same failure blocks once, a different one blocks again, and a pass in between re-arms it. The check gets 150 s; past that its whole process tree is killed (`taskkill /T` on Windows, the process group elsewhere), so no orphaned compiler keeps writing build info. Keep the registered timeout above that budget: a hook the harness kills writes nothing and leaves its checker running.

**The tree key** is `HEAD` plus every changed, untracked or deleted path with a hash of its content (`git status --porcelain -z --untracked-files=all`, run with `GIT_OPTIONAL_LOCKS=0` so it never takes `index.lock` from under the owner's own git command, and with `core.ignorecase=false` so a case-only rename shows as a change). A turn that edits nothing after a passing run costs nothing, and an edit reverted to the original reads as unchanged. Two kinds of path never count: the reviewer's compile probe `<SRC_DIR>/__hunt_probe*.ts`, which comes and goes while a review runs, and `.claude/sessions/`, which holds notes, not code. A personal layer is excluded from the project's git, so its own edits never move the key.

**Output.** A single JSON object on stdout and exit 0, never a bare exit code - a hook that errors must report, never wedge the session (`guard.mjs` is the opposite: stderr and exit 2). A pass stores the key as the last passing one and prints nothing. A failure stores the key as the last blocked one and prints `{ "decision": "block", "reason": <the last 60 lines of the check's output> }`, the reason ending with: a failure in a file this task neither touched nor reaches is the owner's own edit or a parallel session's - say so instead of fixing it. A check that could not run or overran prints `{ "systemMessage": "... Nothing was verified." }` and does not block.

**A check command that outlasts 150 s** overruns on every Stop and verifies nothing there: point `CHECK` at a faster subset of it (type-check and lint, say) and leave the whole chain to lifecycle step 9.

**The key covers the whole tree, unattributed**, so the owner's IDE or a parallel session in the same tree can trigger a run in this session; that is why the block reason says the failure may not be this session's. Nothing else: no review tracking, no waivers, no browser reminder.

**The compile probe.** A team layer excludes `<SRC_DIR>/__hunt_probe*.ts` from the build and lint configs as well (the compiler's `exclude`, the linter's ignore list), so a probe live while a turn ends or while the main thread runs the check cannot fail it - and the probe agent compiles through a project of its own (`hunt.md`), because a probe excluded from the repo's project is not compiled by the repo's command either. A personal layer edits no project config, so there a live probe can fail a check run; the install names that cost.

### What it does not cover

- **Formatting** - a formatter run at commit time stays the only formatting gate.
- **Any tree but its own** - a session editing files in another worktree passes clean while that tree is broken, and a worktree carrying an older copy of these hooks behaves as that copy says.
- **Whether the change was reviewed** - the review ladder lives in `crosscheck`, and the reply names every agent the task ran, so a skipped review is visible there, not here.

## Testing a hook

Never the live hook with a live payload: a real `Stop` payload makes the Stop hook write state for the real session id and run the real check, and a real `PreToolUse` payload runs the guard against the real tree. Copy the hook into the scratchpad, write `payload.json` beside it with `Write`, and run it with every path it reads pointed into the scratchpad:

```bash
S="${TMPDIR:-${TMP:-/tmp}}/hooktest"   # scratchpad, never the repo
mkdir -p "$S/app"
cp "$(git rev-parse --show-toplevel)/.claude/hooks/guard.mjs" "$S/guard.mjs"
CLAUDE_PROJECT_DIR="$S/app" LOCALAPPDATA="$S/cache" TMP="$S" TEMP="$S" \
  node "$S/guard.mjs" < "$S/payload.json"; echo "exit $?"
```

`CLAUDE_PROJECT_DIR` is the project root the guard resolves and `LOCALAPPDATA` holds the Stop hook's state, so both have to move or the run touches the real ones. The Stop hook ignores `CLAUDE_PROJECT_DIR` and takes its root from its own location, so copy `stop-check.mjs` to `$S/app/.claude/hooks/`, give `$S/app` a `.git` (`git init` there - a scratch repo, never the project's), and point its `CHECK` constant at a trivial command in the copy. For the guard the payload is the whole test - `{ "tool_name": "Bash", "cwd": "<app>", "tool_input": { "command": "git commit -m x" } }` - with exit 2 a block and exit 0 an allow. `Edit` / `Write` / `MultiEdit` take `file_path` plus `content` or `new_string`, and `agent_type` exercises the write fence.
