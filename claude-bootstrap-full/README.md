# Claude Code project bootstrap

A project-agnostic copy of a Claude Code working layer built and audited on a production web frontend: one task lifecycle, one review ladder, deterministic guards, and agents fenced to a single job each. Apply it to a new project, fill the project-specific sections, and start working - the project-specific pieces are kept under `examples/` for reference, never copied.

```
README.md                         this file
apply.mjs                         copies template/ into a project, fills placeholders, prints what is left
bootstrap.config.example.json     the answers the example app would give - copy and edit
template/                         what a project receives (CLAUDE.md, .claude/*)
examples/                         project-specific pieces, rewritten onto one invented app, each saying what it depends on
```

## What the setup is

- **One lifecycle** - steps 1-2 in `CLAUDE.md` (Development Workflow), because they run before and inside plan mode; steps 3-10 and the re-entry rules in the `lifecycle` skill, loaded once step 2 closes: investigate and classify, two pre-edit checks, implement, then twins + the editor agents + `comments` in one message and a last `comments` pass over what arrived since, review, browser check after the first round, docs drift once after the last round, name the unverified, one verification call and three suggested commit subjects. The skip rule is stated once, in `CLAUDE.md`; re-entry and parallelism once, in the skill. The editors run together because none of them has the `Write` tool: every change is a string replacement, so two agents in one file cannot lose each other's work, and an overlap fails loudly instead.
- **One review ladder** (`.claude/skills/crosscheck/SKILL.md`): count the risk signals in the diff - a signal counts only when the diff changes what makes the class - and the count picks the tier: `gate` alone, `gate` + `hunt` + one lens, or the full fan-out. A later round re-runs `gate` plus only the legs an accepted finding or the fix diff's own signals call for. Nothing else in the layer says when a reviewer runs.
- **One browser ritual** (`.claude/skills/verify-live/SKILL.md`): the port by fact (`dev-servers.mjs`, Windows as shipped - its header names the `lsof` / `ps` swap), the machine by a marker endpoint, then a read-first pass.
- **The session's own artifact folder** (`.claude/sessions/<start>-<session id prefix>/`): one `task-<slug>.md` ledger per task, `agents.md` with a row per agent launch written by the recorder hook, and the `precompact` handoff. Opened as lifecycle step 1 closes (in plan mode right after approval). The hook never creates the folder, but the first file written into it makes the hook create `agents.md` with every launch this session made before, so no row is ever written by hand; a plan accepted with cleared context runs under a new session id, and its task file carries the plan-mode launches instead. The mechanics live in the one rule the layer ships for itself, `.claude/rules/session-artifacts.md`. `compact-pointer.mjs` names the session id prefix and the folder at session start - the model has no other source for its session id - and carries the path across a compaction. A session never reads another session's folder unless the owner names one to continue.
- **Deterministic guards** (`.claude/hooks/`): `guard.mjs` refuses mutating git (however the binary is spelled, `git stash` by an allow list of `list` / `show`, and a read verb that runs a program or writes a file), `gh`, in-place shell edits, shell writes into the tree, a copy / move into the tree, a delete beyond the one grant (a single non-recursive project path per call, never a protected path, `.git`, the hooks or settings), a `cd` outside a Bash subshell, an interpreter one-liner that writes a file, protected paths, dash characters and any tool creating or overwriting a session's `agents.md`, before the call runs - judging every command both as written and with its shell comments blanked; `hunt` and `integration` it fences to their own compile probe. `verify-gate.mjs` (opt-in) runs the check command at the end of a turn that changed a file, and defers a check to the next Stop instead of failing on a half-finished operation: while this session's own agent that writes the files the check reads is running (any agent outside the read-only set holds the check command), and across sessions only on a collision on disk - another session's `gate` holds the check command, its `hunt` or `integration` the probe check. The checks share a 110 s budget under the hook's 150 s timeout; a check that runs past it is killed with its process tree and is not a failure. `record-activity.mjs` writes down which agents ran - each launch paired with its own finish by agent id, running for 60 minutes at most - and which files the model edited, so the gate can also block a turn when this session changed source after its last `gate` launch - the one obligation in the layer that otherwise leaves no trace. After a block, re-edits of the files it named stay quiet until a `gate` launch or a waiver answers it, and an edit of a file it did not name blocks again. A deliberate skip is a reason written into the per-session waiver the block names, `.claude/.gate-waivers/review-<session id prefix>`; there are no per-check waivers. `gate-registered.mjs` says at session start when a tree has no gate at all, and `upkeep-nudge.mjs` when the `maintain-ai-layer` pass is 14 days overdue (it reads the date the pass writes into the gitignored `.claude/.last-maintain`, and stays silent in a linked worktree). `record-loads.mjs` logs every `CLAUDE.md` and rule load for `rules-reach.mjs --loads`. The deny list in `settings.json` is the backstop behind the guard.
- **Agents with fences**: `gate` (static review, read-only), `hunt` (runtime defects only, attack-angle library, probes, plan-review mode, plus an `area` audit of a path scope and a `refute` pass over another run's findings, both in `.claude/docs/hunt-modes.md`), `integration` (what line-level review misses: packaging reach, storage keys, cache interactions, cliffs - probes, otherwise read-only), `twins` (same pattern elsewhere, read-only), `drift` (doc claims vs code, read-only, `dead` verdict, and after a fix the one missing rule for a defect class no doc warned about, gated by five conditions - zero is the normal result), `comments` (edits comment text only, on the comments the diff adds or changes - a pre-existing one the diff made false is reported, not edited - and deletes by default - ticket ids, history, measurement notes and process chatter go unconditionally). `gate`, `hunt`, `integration` and `twins` open their report with a one-line verdict token, `drift` and `comments` close theirs with a tally line, so the main thread does not have to parse prose to know what happened. An editor that owns one artefact (translations, generated notes) follows the model in `examples/i18n.md`. Every editing agent carries the same rule: a refused `Edit` is re-read and retried once, then reported as **not applied** - never as done.
- **Rule reach** (`.claude/scripts/rules-reach.mjs`, mechanics in `.claude/rules/rules-reach.md`): a path-scoped rule that does not load where its code lives is a rule that does not exist, so the globs are proved, not trusted. `--check` refuses the glob shapes where the loader and `matchesGlob` disagree and runs `rules-reach.fixture.json` - a `must` pair per file that needs a rule, with a needle from the paragraph it needs, and `mustNot` pairs. Without arguments it reports the rule bytes each source-file read pulls in. `--loads` replays the loads `record-loads.mjs` logged against the script's model of the loader, so a loader change shows up as a mismatch instead of a green `--check` on a wrong model. The Stop gate runs `--check` on its own when only a rule or the fixture changed.
- **Settled decisions** (`.claude/docs/decisions.md`, tracked - `.claude/docs/` is the folder for team docs that load nowhere by themselves - this one and `hunt-modes.md`, which `hunt` reads for its `area` and `refute` modes - never the overflow of `CLAUDE.md`): the won't-dos, out-of-scope items, rejected fixes and verified-clean claims about single sites. `crosscheck` greps it by the diff and hands each matching entry to every reviewer as settled, and a reviewer reports a match as `settled (decisions.md)` in Observations instead of re-filing it; `drift` reads it first. Project-wide decisions stay in `CLAUDE.md`. Entries are the owner's.
- **Skills**: `lifecycle` (steps 3-10 - process text only the main thread uses, so it stays out of `CLAUDE.md`), and for the two moments the lifecycle branches, `debug` (root cause before any fix) and `precompact` (the handoff file). `retro`, on the owner's request after a task, turns the session's record - the task file, the ledger, every correction the user had to make - into numbered improvements, each fixed at the cheapest layer that would have caught it (a failing tool before a `CLAUDE.md` line before a rule before a skill step before a memory entry), each with a default; nothing changes until the user answers. `maintain-ai-layer` is the recurring upkeep of the layer itself, one `references/<mode>.md` per mode: `weekly` runs the mechanical checks (`layer-refs.mjs` for dead paths, scripts, skill and agent names; `rules-reach`; the counts) plus `drift` on the rules the last two weeks of code touched, `deep` a `drift` pass over every unit, the `rules` steps, the memory folder and a walk of whole tasks through the lifecycle, `rules` the rule set alone - each rule checked against the code, its globs measured for over- and under-reach (`rules-reach.mjs --files`), a probe of the rule loader, a rule whose sections serve different files split, new rules from a sweep of the code and its fix history, and with no project rule yet, a whole set built from the project - all three applying what they verified themselves, reporting hooks, settings and settled decisions; `efficiency` measures where the pipeline is slow or spends tokens with no result (the one mode that reads past the session boundary, for statistics) and stops for the owner's answer before applying. Plus `setup`, which the project runs once after `apply.mjs`: it reads the repo, merges with whatever Claude config was already there, writes the `[fill]` sections, tunes the signal list and the attack angles to this project, and runs the self-tests.

## Placeholders

`apply.mjs` replaces these in every text file of `template/`; an unknown `<UPPER_CASE>` token is left alone and reported.

| Placeholder | Meaning | Example value |
| --- | --- | --- |
| `<PROJECT>` | project name | `stockroom` |
| `<STACK>` | the stack in one line, goes into the agents' first sentence | `React 19 + TypeScript strict on Vite, MUI, ...` |
| `<SRC_DIR>` | source directory, no trailing slash; also the import alias `run-pure.mjs` resolves | `src` |
| `<CHECK_COMMAND>` | the one verification call; the gate, the Stop gate and the allow list use it | `npm run check` |
| `<DEV_PORT_RANGE>` | ports `dev-servers.mjs` scans | `5173-5179` |
| `<DEV_BASE_PATH>` | the app's base path with both slashes; the marker lives at `<DEV_BASE_PATH>__tree` | `/stockroom/` |
| `<GENERATED_PATHS>` | JSON array of regex sources the guard refuses to edit, forward slashes | `["src/api/[^/]+/generated/", "\\.openapi\\.json$"]` |

## Apply

```bash
node apply.mjs D:/path/to/project --config answers.json     # answers as JSON (start from bootstrap.config.example.json)
node apply.mjs D:/path/to/project                           # or answer the questions on the terminal
node apply.mjs D:/path/to/project --config answers.json --dry-run
node apply.mjs D:/path/to/project --config answers.json --force   # overwrite files that already exist, but never CLAUDE.md or settings.json
```

Without `--force` an existing file is kept and listed - except the project's own `CLAUDE.md`, which is also kept while the layer's copy lands beside it as `CLAUDE.bootstrap.md` for `/setup` to merge and then delete (a re-run keeps that copy too, so a merge in progress is never overwritten). `--force` overwrites the rest, `CLAUDE.bootstrap.md` included, but never the project's `CLAUDE.md` or `.claude/settings.json`. `.gitignore` gets the `.claude/*` deny-by-default block when it has no `.claude/*` line yet (a block already there is left alone, so `/setup` proves with `git check-ignore` that the layer is tracked and the personal paths are not); a bare `.claude/` line is reported instead, since it hides the whole layer. `.claude/sessions/` is deliberately left un-negated there, so each session's own folder stays untracked. The values land in JS and JSON string literals, so the script refuses quotes and backslashes in them. It ends with the manual steps, in order - the same list as below.

### After applying

**Start Claude Code in the project and run `/setup`** (`.claude/skills/setup/SKILL.md`). It does steps 1 to 7 and 9 below by reading the repo, and the deletion half of step 8; the marker endpoint itself is a source change and stays with the owner. It asks in chat what the repo cannot settle, and merges with a `CLAUDE.md` or a `settings.json` the project already had rather than overwriting them (the layer's own `CLAUDE.md` arrives as `CLAUDE.bootstrap.md` when the project has one). The list below is what must end up done, whoever does it.

1. `CLAUDE.md`: write every `[fill]` section (`grep -n "\[fill\]" CLAUDE.md`), delete the bootstrap note at the top. Keep it under 48 000 bytes (`wc -c`); the budget rule inside says what to do when it grows.
2. `twins.md`: the known-twins list. `comments.md`: what other agents own. `lifecycle`: the project's editor agents at step 4. `maintain-ai-layer`: the three source areas of step R5 (`references/rules.md`), and `PREFIXES` in its `layer-refs.mjs`. `crosscheck`: the signal list, one entry per class that has produced a runtime bug in this project. `verify-live`: every `[fill]` line.
3. `hunt.md`: the attack angles are written for a browser frontend - keep the shape, replace the classes the project does not have, and feed it every bug that surfaces after a review (`examples/hunt-example.md` shows what a fed library looks like).
4. Self-test the hooks from the project root: `node .claude/hooks/tests/guard-test.mjs && node .claude/hooks/tests/guard-shell-test.mjs && node .claude/hooks/tests/upkeep-nudge-test.mjs` - every line `ok`. Add a case per protected path (two commented lines in `guard-test.mjs`). The suites only pass after `apply.mjs` has filled the placeholders; in `template/` they fail on `<GENERATED_PATHS>` by design.
5. **Exclude the probe path from the build and lint configs** - `<SRC_DIR>/__hunt_probe*.ts` in the compiler's `exclude` and the linter's ignore list - so a probe live while `gate` runs does not fail the check command and get blamed on the diff. Then check the two probe agents' own compile recipe still sees the probe: a project that excludes it does not compile it either, which is why `hunt.md` and `integration.md` build a project of their own in the scratchpad. Prove it once with a deliberately broken probe: the repo's project exits 0, the scratchpad project reports the error.
6. Add `node .claude/scripts/rules-reach.mjs --check` to the check command (it needs Node 22.5+ or 20.17+ for `path.matchesGlob`, and git), and run it once: the two shipped rules and their fixture pairs must pass.
7. Optional Stop gate: copy `.claude/settings.local.example.json` to `.claude/settings.local.json` in every worktree. It also sets `CLAUDE_CODE_MAX_RETRIES=15` (the cap) so an API outage is retried longer before the turn dies. It waits on this session's own writing agents by itself; a project editor agent that owns one checker gets that checker split out of `CHECKS` in `verify-gate.mjs`, deferred on the agent (`.claude/hooks/README.md`).
8. Browser projects: add the marker endpoint (`examples/tree-marker-plugin.ts` is the Vite version) - and have it report the **listening** port, not the configured one, or it names another tree's server the day two trees run at once. No UI: delete `skills/verify-live/`, `scripts/dev-servers.mjs`, the "running app" block in `CLAUDE.md`, and rewrite step 7 in `skills/lifecycle/SKILL.md` as the command that exercises the change.
9. The project's first path-scoped rule goes into `.claude/rules/` beside the two the layer ships (`rules-reach.md` says how a rule loads and what goes into one), with a `must` pair in `rules-reach.fixture.json` for the file that needs it. Point each rule's globs at the files that actually call the thing, then measure with `node .claude/scripts/rules-reach.mjs`: a rule that does not load at the call site is a rule that does not exist, and a glob matching a third of the tree is paid on every read.
10. Start a new session: agents and skills are read at session start, and a running session is not guaranteed to pick up hook registrations.

## Verify the layer works

- Guard: the two test suites above (git verbs behind `-C` / `-c`, `git stash`, a read-only git verb that runs or writes (`git grep -O`, `--output`), a variable set to a literal path before it is used, the agents' write fence, interpreter one-liners, `gh`, `sed -i`, heredocs and `tee` by target, a copier's source versus its destination, the delete grant and its cap, `cd` outside a subshell, a `# it's` comment hiding a later line, the `agents.md` ledger, dashes in `Edit` / `Write` / `MultiEdit`, files outside the project).
- Rule reach: `node .claude/scripts/rules-reach.mjs --check` ends with `0 failed` and no `SHAPE` line. Once a session has Read a file a rule matches, `node .claude/scripts/rules-reach.mjs --loads` ends with `0 mismatches`; `nothing recorded` means `record-loads.mjs` is not firing. They print one line per case and end with the count, so no number needs to live here.
- Stop gate: register it, edit a source file, end the turn with the check command failing - the turn is blocked once with the output, and a second Stop on the same tree state only reports.
- `run-pure.mjs`: a probe importing `<SRC_DIR>/<module>` runs under Node with the alias resolved and `window` shimmed.

## Writing rules for the layer

These are what the layer's own audits paid for; the files follow them and additions should too.

- **A skill or agent description is a trigger, never a summary.** A description that summarizes the workflow makes the agent skip the skill body and work from the summary (documented failure in the superpowers library). Say when to load it and what the user says; keep the how inside.
- **Each mechanic lives in exactly one file.** The lifecycle in `CLAUDE.md` (steps 1-2) and the `lifecycle` skill (steps 3-10), the ladder in `crosscheck`, the browser ritual in `verify-live`. Another file may point, never restate.
- **A count or a site list rots.** Write the grep that finds the sites.
- **Delete what is true but dead**: a status, an instruction for a change already applied, an alternative nothing uses, a paragraph another loaded file already says. A fact-check alone leaves it standing; `drift` has a `dead` verdict for it.
- **Prohibitions stay in `CLAUDE.md`**; a path-scoped rule fires after a matching file is read, too late for "never create X". Point rule globs at what the rule describes, not at everything it governs, and measure bytes-of-rules-per-file-read.
- **Form matches the failure.** A prohibition the model keeps rationalizing past gets a hook, not a stronger adjective; a step it skips gets "name each skill and agent the task ran" so the skip is visible.
- **Reviewers get "deliberate - here is why", never "do not flag".** A no-flag list inherits the implementer's blind spots.
- **Every agent pins a model and `effort: high`.** The alternative, inheriting the session's, means the review gets quietly cheaper exactly when the session is running cheap - which is when it is needed most. Drop the two lines only where the owner deliberately wants a cheaper agent.
- **An instruction that can be verified by a command is verified by the command, not believed.** Two of the bugs this layer's own audit found were invisible to reading and obvious to one run: a dev-server marker that printed the configured port rather than the listening one, and a build-config exclusion that hid a compile probe from the very command the probing agent was told to run. Write the check next to the claim.
- **Agents never see images.** Whatever a screenshot showed is transcribed into the Brief that every agent prompt carries.
- **Every file of the layer is in one language**, trigger phrases in descriptions included - the model matches a request written in another language by meaning. The reply follows the user's language by the Working Principles rule, which names no language itself.
- Plain hyphens everywhere; the guard refuses a dash in any file under the project (delete the check together with the Punctuation section if the project does not want it).

## Facts about Claude Code this layer relies on

- A hook script is read on every call, so an edit to it applies at once; a changed registration in `settings.json` / `settings.local.json` is not guaranteed to reach a running session (one added mid-session did fire on the next compaction); agents and skills are read at session start.
- `PreToolUse`: exit 2 + stderr blocks the call and shows the reason to the model. `SessionStart`: `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"..."}}` on stdout injects context. `Stop`: `{"decision":"block","reason":"..."}`; `stop_hook_active: true` means it already fired this turn - never block again.
- `PostToolUse` matches the subagent launch as tool name `Agent`, and its payload carries `tool_input.subagent_type`; the call's result carries the agent id. `SubagentStop` carries `agent_type`, `agent_id` and the parent session's id (measured), so a launch pairs with its own finish by id and every record can be read per session. Continuing an agent through `SendMessage` records no launch.
- The public hooks reference documents no output fields for `PreCompact` or `PostCompact`. Send `systemMessage` alongside whatever else you try, so a pointer is not lost to an unsupported channel.
- The browser tools record nothing before their own first call: `read_console_messages` and `read_network_requests` answer "none found" for everything that happened earlier, which is indistinguishable from a clean run. Arm them right after the marker navigation, before navigating to the app - a fresh tab still on the browser's internal new-tab page refuses both.
- A file's write record outlives the file. Anything that reasons about "what this session edited" checks that the path still exists, or a probe created and deleted in one turn keeps demanding attention.
- `${CLAUDE_PROJECT_DIR}` in a hook command resolves per tree; `settings.local.json` is not carried into a new worktree.
- A deny in `permissions` outranks every allow at every scope and matches the raw command string only.
- `CLAUDE.md` is read up to 4 MiB; the 48 KB budget is the project's own. `MEMORY.md` is read up to 200 lines / 25 KB.
- `CLAUDE_CODE_MAX_RETRIES` defaults to 10, caps at 15. `claude --resume <id>` continues an interrupted turn.
- The Bash tool eats backslashes in its arguments; a regex or path with backslashes is built in a script file, or with `String.fromCharCode`. The working directory persists across calls, so a `cd` in a chain retargets every later relative path.
- The Grep tool skips gitignored paths unless the folder is passed as its path, and misses files when its `path` is `.claude` itself - ripgrep misapplies the `.claude/*` ignore-plus-negation lines at that root, so a zero- or low-hit answer there proves nothing. Search `.claude` from the repo root with `glob: '.claude/**'`, or pass a subfolder.
- The hooks read payload fields Claude Code does not promise to keep (`session_id`, `agent_id`, `agent_type`, the tool names `Agent` and `mcp__claude-in-chrome__navigate`). A renamed field fails silently: an agent launch that leaves no row in `agents.md` means a field moved.
- A path-scoped rule loads in full when the Read tool opens a matching file, once per context - after `/compact` it loads again on the next matching Read. Glob, Grep, Write and Edit load nothing, a Bash command that reads the file (`head`) does, a subagent's Read loads into that subagent only, and a rule whose own file was already Read is not injected again. Only the Read trigger is documented; the rest is observed, and `maintain-ai-layer deep` re-probes it. A rules file without `paths:` loads on every session. The loader expands every brace group, strips a trailing `/**` and matches with gitignore semantics: a glob with an inner slash is anchored at the root, a slash-less one (a folder glob such as `nginx/**` included, once stripped) matches at any depth; there is no negation.
- `InstructionsLoaded` fires for every `CLAUDE.md` and rule load - at session start, on a matching Read, after a compaction, in a subagent too - and is not awaited, so its hook cannot block. Its payload carries the loaded file, the load reason, the trigger path and the rule's globs; since 2.1.296 a subagent's load also carries `agent_id` and `agent_type`, and a main-thread load neither (measured).

## examples/

Reference only. They come from a real project and are rewritten onto one invented app - Stockroom, an inventory analytics frontend (React + TypeScript on Vite, en / de) - so the names, endpoints and decisions in them are illustrations, not facts to copy. `i18n.md` (an editor agent fenced to one artefact, with its checker `i18n-check.mjs`), `hunt-example.md` (the fed attack-angle list), `rule-queries.md` (a path-scoped rule with a measured glob list), `decisions-example.md` (a filled `.claude/docs/decisions.md`), `verify-live-example.md` (the ritual with real endpoints), `tree-marker-plugin.ts` (the Vite marker), `bundle-report.mjs` (per-route static JS and chunk invariants from two production builds, for changes a dev server cannot show), `pretty-json.mjs` (re-indents a captured JSON body without re-stringifying it, for a backend-request draft), and three skills that need a tracker, a backlog or a second worktree (`fix-improvements`, `backend-request`, `integrate-worktree` with the team's hand-run `worktree-flow.md` beside it). The examples name a personal gitignored folder `localDocs/` (the backlog, the backend-request drafts under `localDocs/backend-requests/`) - a project adopting one of them picks its own.
