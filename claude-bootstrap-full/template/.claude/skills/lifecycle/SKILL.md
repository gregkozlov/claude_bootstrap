# lifecycle

Steps 1-2 (classify, the Brief, the questions, the consumer walk, `hunt` on a plan) and the skip rule are in `CLAUDE.md`. This skill carries steps 3-9. A tier-0 change (`crosscheck`) runs steps 3, 8 and 9 only, plus each project editor agent of step 4 on its own condition, and step 6 when the browser can show it; it owes no commit subject.

3. **Implement** in the main thread, then walk the step-2 consumer list yourself. Code restored from git history is checked against the layer as it is now: `git log -p <the commit that stripped its doc text>^..HEAD -- CLAUDE.md .claude/rules` lists the rules written since, which it never obeyed and no lint enforces, and the stripped text comes back adjusted, not reverted. Then load `crosscheck` and pick the tier - it decides whether step 4 runs.
4. **First batch, one message:** `twins`, `comments`, and the project's own editor agents on their conditions ([fill] list them with their conditions - one per artefact the main thread should never hand-edit (translation files, generated notes, a changelog), each owning its files exclusively - or delete this clause; `examples/i18n.md` in the bootstrap's own folder is the model). They run together because none can lose another's work: `twins` is read-only, and every editor agent here is given `Edit` but **not** `Write`, so each change is a string replacement against the file as it stands rather than a whole-file overwrite. Where an `old_string` does overlap, the `Edit` fails loudly and the agent re-reads and retries - which is why every editor agent's definition must carry that retry rule and must report a still-refused edit as **not applied**. `twins` never edits - apply the sites it reports that hold before the review, so the widened diff is reviewed once. `comments` runs once per task, over the comments the diff adds or changes; the comments a later edit adds are cut by the main thread, by the comment policy. An editor agent runs again whenever a later edit (a `twins` patch, a review fix, a live-probe fact) moves its artefact. When an agent returns, read its report and `git diff --stat`: its "done" is a claim, the hunks are the evidence.
5. **Review.** `<CHECK_COMMAND>` (Bash or PowerShell `timeout` long enough for the whole chain, up to 600000, awaited) passes first; then do what `crosscheck` says for the tier - the reviewers in one message. Every finding of `twins`, `gate`, `hunt` and `drift` is checked against the code and the reachability bar (`CLAUDE.md`) and accepted or rejected with a one-line reason in the task file; the edits of `comments` and the editor agents need no review. A count or a `file:line` from a report is recounted when a fix or another prompt rests on it.
6. **Browser check - whenever the change can be seen.** Load `verify-live` and run it after the review round returned, so the app is looked at against a diff that has stopped moving; the `crosscheck` live probes are this visit's additions. A later fix that changes what renders gets a re-check of that surface alone. "It should work" is not a reason to skip it. **Never start a dev server.** When nothing listens for this tree, or the browser cannot reach the app (no browser connected, an error page, the login page), the check is pending: run steps 7-9, say so, and ask the owner to step in - never mark it unverified and move on. [fill] For a project with no browser UI this step is the command that exercises the change and its output.
7. **Docs.** Grep `.claude/` for every identifier the diff renamed or removed, and fix what became false. At tier 3, `drift` runs in `diff` mode after the last round as well, its prompt carrying the task file's findings with their decisions as settled: apply its replacements for drift the diff created, send pre-existing drift to the user, and apply a proposed gap only when it is one line in the path-scoped rule for a reachable defect class.
8. **Name what stays unverified** - the one to three things that need the user's data, eyes or judgement and can really be wrong (a value scale nobody measured, a write path never exercised, a layout at another font size), each with what to look at. Beside it, every decision taken on the user's behalf - a default picked, a reading chosen between two, a scope drawn - one line each with what it costs if wrong; a decision that stays in the transcript was made in secret. The findings ledger (`crosscheck`, Report) goes in the same reply.
9. **Verify once:** `<CHECK_COMMAND>`, with a `timeout` long enough for the whole chain (up to 600000), awaited to its exit - unless nothing changed since step 5's passing run, which then stands - even though the Stop hook runs a check too: an overrun there ends in "Nothing was verified", never a pass, so it never stands in for this call. Then end the closing reply with three commit subjects.

## Commit subjects

The user commits, never this thread. Derive the subjects from the final `git diff`, not from the brief, and match what the repo does - read `git log --format='%s' -50`, not a remembered convention:

- The prefix set, case, scope style and punctuation the log shows; one line, the outcome in the product's own words.
- No ticket id unless the log shows the repo's subjects carry one.
- Vary the three by angle, not wording: what broke, what the user now sees, what the code now does. Two unrelated concerns get subjects per commit.

## Re-entry

**A widened scope re-enters at step 2 and closes before any reviewer is launched** - the user adds a surface mid-task, or you take the `twins` sites. Grep the new surfaces' consumers, implement them, and only then run step 5. **A task that turns out to change a contract** (found while implementing, or named in a `hunt` / `gate` report) **re-enters as architectural**: stop editing, write the plan with its consumer list from the edits so far, the task file's Brief, the decisions taken on the user's behalf, the adjudicated findings and the open risks (a cleared-context approval cannot read this session's folder), run `hunt` on that plan, get approval, then continue at step 3 at tier 3.

**A change made after step 5** - a review fix, a browser-check fix, a late `twins` patch - re-runs only what it invalidates: an editor agent by step 4's rule, `<CHECK_COMMAND>`, and the second round when `crosscheck` says one is owed.

**A change that touches nothing under `<SRC_DIR>/` or the config files ([fill] list the project's other source and config paths - static assets, the package manifest, compiler / bundler / lint / formatter configs, the HTML entry, container and server configs) skips steps 4-6**, except that code it changes under `.claude/hooks` or `.claude/scripts` still gets the step-5 review `crosscheck` gives that code. Step 9 always runs, and step 7 above tier 0.

## The session folder

- The name is `.claude/sessions/<yyyy-mm-ddThh-mm>-<first 8 of the session id>/`, in local time, the id taken from the SessionStart hook's context line - never guessed. `compact-pointer.mjs` finds the folder by that suffix and never creates one, so a folder under another name gets no compaction pointer.
- `task-<slug>.md`, for every bounded or architectural task: the Brief, the file list, the consumer list, each finding with its decision in one line, the decisions taken on the user's behalf, the open risks. Open it as step 1 closes - in plan mode right after approval, carrying the plan's `hunt` findings and their decisions - and write it as the steps close; never paste a report into it.
- `handoff.md` is the `precompact` skill's. Only this session's main thread writes in the folder. A folder the user names to continue is read (its `handoff.md` and task file), never adopted: everything new goes into this session's own folder.
