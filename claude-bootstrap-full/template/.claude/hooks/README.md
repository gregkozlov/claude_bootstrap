# Hooks

Four dependency-free Claude Code hooks (Node 18+, no packages), every script and every registration tracked in `.claude/settings.json`, so a tree has them once its `.claude` folder exists.

| Hook | Event | Registered in | What it does |
| --- | --- | --- | --- |
| `guard.mjs` | `PreToolUse` on `Bash`, `PowerShell`, `Edit`, `Write`, `MultiEdit` | `.claude/settings.json` (tracked - repo policy, like the deny list beside it) | Refuses a tool call CLAUDE.md forbids outright, before it runs |
| `upkeep-nudge.mjs` | `SessionStart` (startup, clear) | `.claude/settings.json` (tracked) | Says so when the `maintain-ai-layer` pass is 14 days overdue, or never ran in this tree |
| `compact-pointer.mjs` | `SessionStart` (startup, resume, clear, compact) + `PreCompact` + `PostCompact` | `.claude/settings.json` (tracked) | Names this session's artifact folder. `SessionStart` hands the model the session id prefix and the folder it has, or the name to open one under (`additionalContext`), and on `compact` where to resume from; `PreCompact` and `PostCompact` name the folder to the user (`systemMessage` - the harness rejects `hookSpecificOutput` on `PostCompact`), and on a manual `/compact` `PreCompact` says a handoff needs `/precompact` first. Both compaction events stay silent when the session has no folder |
| `stop-check.mjs` | `SessionStart` (startup, resume, clear, compact; timeout 30) + `Stop` (timeout 180) | `.claude/settings.json` (tracked) | Runs `<CHECK_COMMAND>` at the end of a turn when the tree moved off the session's start state, and blocks once on a failure |

After changing a hook registration in a settings file, start a new session: a running one is not guaranteed to pick it up.

The hooks read payload fields Claude Code does not promise to keep (`session_id`, `agent_type`, `stop_hook_active`, `hook_event_name`). A renamed field fails silently - check the payload before trusting the Stop hook or the write fence.

**No hook picks up another session's handoff.** Several sessions can run in the same tree at once, and a handoff belongs to one task, not to whoever starts next. The handoff lives in the session's own folder under `.claude/sessions/` and is handed over by hand - the `precompact` skill ends by printing the sentence to open the next session with. Do not add such a hook. `compact-pointer.mjs` is not that hook: it names only the folder of the session it fires in, and never reads another one.

## Facts about the hook protocol this layer relies on

- A hook reads one JSON payload on stdin: `hook_event_name`, `session_id`, `cwd`, plus `tool_name` / `tool_input` (and `tool_response` after the call) for a tool event, `source` for `SessionStart`, `trigger` (`manual` or `auto`) for `PreCompact`, `stop_hook_active` for `Stop`. `CLAUDE_PROJECT_DIR` is set in every hook's environment, and `${CLAUDE_PROJECT_DIR}` in a registered command resolves per tree.
- `PreToolUse`: exit 2 with the reason on stderr blocks the call and shows the reason to the model; exit 0 allows it.
- A subagent's own tool call carries the **parent** session's `session_id` plus its `agent_id` and `agent_type` (measured) - which is what the guard's write fence reads.
- `SessionStart`: `source` is `startup`, `resume`, `clear` or `compact`; stdout JSON `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"..."}}` injects text into the session's context. A `startup` can keep a session id that already has state - the id survives a restart (measured).
- `Stop`: stdout JSON `{"decision":"block","reason":"..."}` makes the model continue with the reason; `systemMessage` reaches the user only, never the model. There is no third channel - a Stop hook cannot tell the model anything without blocking. `stop_hook_active: true` means the Stop already fired once for this turn - never block again then, or the session loops. A hook still running at its registered `timeout` is killed and writes nothing.
- `PreCompact` / `PostCompact`: `systemMessage` reaches the user. `PostCompact` rejects `hookSpecificOutput` (measured at a real `/compact`), so `compact-pointer.mjs` sends `systemMessage` alone on both and hands the model its pointer through the `SessionStart` whose `source` is `compact`.

## guard.mjs - the PreToolUse guard

Deterministic, milliseconds, no state. Exit 2 with the reason on stderr blocks the call; exit 0 allows it; input it cannot parse is allowed (the deny list in `settings.json` and the rules still stand behind it). It is a best-effort net for a well-meaning model, not a security boundary.

- **Git.** Every `git` occurrence is judged wherever it sits - behind `git -C` or `-c`, inside `$(...)` or backticks, after `xargs` or `cmd /c`, as `git.exe` or a quoted path to the binary, and inside an interpreter one-liner or an argv array (`["git", "stash"]`, escaped quotes included). Refused: the verbs in `GIT_WRITE_VERBS`, the writing subcommands in `GIT_WRITE_SUBCOMMANDS`, `apply` without `--check` / `--stat` / `--numstat` / `--summary`, `merge-file` without `-p` / `--stdout`, a `config` write, `symbolic-ref` with two operands, and `branch` with a delete, move, copy, force or upstream flag. `stash` is judged by an allow list instead: only `git stash list` and `git stash show` pass, since a bare `git stash -m <msg>` pushes and its first non-flag token is the message; the `settings.json` deny entries name the same writing forms (bare `git stash`, `git stash -...` and each writing subcommand). `git tag --list` stays refused by design. A text search (`grep`, `rg`, `findstr`, `Select-String`) and a read verb's quoted argument (`git log -S "git add"`) are text, unless the segment runs a `$(...)`.
- **`gh`** is refused when it creates, merges, edits, closes, reopens, locks, transfers or deletes anything, checks out a pull request, runs, cancels or toggles a workflow or run, or sets a secret, variable or label, and for `gh api` with a non-GET method or, with none given, a field flag - except a `graphql` query with no `mutation`.
- **Read git that runs or writes**, for anyone: `git grep -O<cmd>` / `--open-files-in-pager` (clustered as `-nOcat` or abbreviated as `--op=` too) starts a program and any verb's `--output[=]<file>` writes one, judged on the words git receives (quotes and escapes resolved, so `-"O"cat` counts). The read-only git prefixes in `settings.json` (`git diff:*`, `git log:*`, `git show:*`) would approve `--output` with no prompt.
- **Interpreters and nested shells.** A one-liner (`node -e` / `-p`, `python -c`, `py -c`, `pwsh -Command`, `iex`) is refused when a write API in it (`writeFileSync`, `rmSync`, `open` with a write mode; `copyFileSync` / `renameSync` / `shutil.copy` on the destination, a rename on its source too) names anything but a literal scratch path - a computed path cannot be proven scratch; the same holds for a script an interpreter reads on stdin (`python - <<'EOF'`, `node <<EOF`, `... | node`), judged over the whole command. A `.NET` write (`[IO.File]::WriteAllText`, `Copy` / `Move` / `Replace`, `[IO.Directory]::Delete`) is judged the same in any command. The string body of `bash -c`, `sh -c`, `cmd /c`, `pwsh -Command` and `iex`, every `$(...)` outside single quotes and every bash backtick pair is checked again as a command line, read with the outer tool's own quoting.
- **Working directory.** `cd`, `chdir`, `pushd`, `popd`, `Set-Location`, `sl`, `Push-Location` and `Pop-Location` are refused at the head of any top-level command, because the cwd persists across calls and into another worktree. Only a Bash subshell - `( ... )`, `$(...)`, a `bash -c` body - may change it; PowerShell has no subshell, so its parentheses and script blocks do not count, and its `cd..` / `cd\` shortcuts are refused too. The refusal names the retry form for its shell: the subshell in Bash, absolute paths, `git -C` or `npm --prefix` in PowerShell. This and every other command check judge each command twice - as written and with its shell comments blanked, a `bash -c` / `pwsh -Command` body likewise with its own shell - and refuse if either view does, so an apostrophe in `# it's` cannot open a quote that hides the lines after it, while the blanked view can only add a refusal, never lift one. Blanking takes a `#` that is a whole word (after unescaped whitespace or `;&|`, outside `${...}`) to the line end or, inside a backtick body, to its closing backtick, and PowerShell's `<# ... #>` only at a word start.
- **Movers.** `cp`, `mv`, `install`, `dd`, `truncate`, `patch`, `shred`, `rsync`, `robocopy`, `xcopy`, `ed`, `ex`, `rm`, `tee`, `unlink`, cmd's `copy`, `move`, `del`, `erase`, `rd` and `rmdir`, the PowerShell `*-Item` cmdlets and their aliases, `Clear-Content` and its alias `clc`, `Tee-Object`, and the downloaders' output flags (`curl -o`, `wget -O`, `-OutFile`) are judged at command position, after leading keywords, assignments, `$null =`, `[void]`, wrappers and an unquoted `cmd /c` are stripped, with commands split at `;`, `|`, `&`, newlines, parentheses and braces outside quotes. A mover is refused when a target is not provably scratch or outside the project (a relative path never is), when a target is a variable the guard cannot resolve (only the scratch variables under Shell writes resolve, plus, in Bash, a name a leading statement sets to a literal - `O="/tmp/out"; cp a "$O/b"` is judged as `cp a "/tmp/out/b"` - unless the rest of the command assigns, loops over, reads into or unsets it, or any leading value holds shell syntax or a quoted leading `~`, or any leading name is one Bash sets itself (`_`, `IFS`, `PWD`, `RANDOM`), or the command holds a comment, a heredoc, `eval` or other grammar the scan does not follow; a skipped substitution, a rebound name and a `${S%/}` form each leave a scratch name whose leading value is not scratch unresolved, so `S=<SRC_DIR>; ... # x` is refused rather than passed by name), or, unless it is `tee`, `Tee-Object` or a downloader, when it has no target. A PowerShell parameter's value is not a path (`-ErrorAction`, `-ItemType`) while `-Path` / `-Destination` are, and a copier's only write is its destination. A comma-joined target (`Remove-Item a,b`) is split and every part judged on its own. `find ... -delete` / `-exec rm` is refused unless every root is scratch, and a mover behind `xargs` always.
- **Inside the project** `MOVER_EXEMPT` at the top of the script passes any mover: anything under `node_modules`, judged after `..` is resolved, and the compile probe `<SRC_DIR>/__hunt_probe*.ts`, which a review agent is required to delete and has no other way to; a project's own exemptions go into `MOVER_EXEMPT`. No other copy or move into the project passes, whatever its flags.
- **The delete grant.** A delete (`rm` / `del` / `Remove-Item` / `unlink`) of a file the change itself orphaned passes with no recursive flag (`-r`, `-R`, `-rf`, PowerShell `-Recurse` or any `-Re` prefix, cmd `/s` or `//s`, clustered as `/s/q` too), never a glob, never a `del` of a directory (it empties it), and **one project path per call**, counted across a chain (`rm a; rm b` is two) - the compile probe counts toward that cap, a path under `node_modules` does not - and never on a path matching `PROTECTED_PATHS`, `.git`, `.claude/hooks/**` or `.claude/settings*.json`, each judged after `..` is resolved.
- **Shell writes.** Refused when the command edits a file in place (`sed -i`, `perl -i`, `awk -i inplace`, `Set-Content` / `Add-Content` / `Out-File`, `prettier --write` / `-w` and `eslint --fix` through `npx`, `bunx`, `pnpm`, `yarn` or `npm exec`, `lint --fix` through `npm run`, `pnpm`, `yarn` or `bun`, `biome --write`) - with no scratch exemption, since the target of an in-place edit cannot be told from the rest of the command - or redirects into a file (`>`, `>>`, `2>`, `>|`, `>&`, `&>`, a quoted target too; `2>&1` names no file, and `tee` is a mover) whose target is not provably scratch: `/dev/null`, `$null`, `NUL`, an absolute path outside the project (an ancestor of it, or a glob in one, counts as inside; a `\\?\` prefix is ignored), a `~/` path containing `/tmp/`, `Temp` or `scratchpad`, or a variable naming one (`$S`, `$TMP`, `$TEMP`, `$SCRATCH`, `$TMPDIR`, `$M`, `$env:temp` / `$env:tmp`, `%temp%` / `%tmp%`). A scratch variable is read as written unless a leading Bash statement sets it to a literal (see Movers); any other path is judged after `..` is resolved, and `$PWD`, `%CD%` or `$(pwd)` name the project, so `./tmp/x` is refused like any other relative path or unknown variable - repo files are changed with `Edit` / `Write`. Every other quoted span is data, so a `>` inside a search pattern is not a redirect; a heredoc body is not quoted, so one that mentions a banned form or a `>` is refused too - notes and scripts go through `Write`.
- **`Edit` / `Write` / `MultiEdit`**: refused for a path matching `PROTECTED_PATHS` - regex sources at the top of the script, filled at install from `<GENERATED_PATHS>` (`INSTALL.md`; a placeholder left unfilled reads as an empty list) and tested against the tool's `file_path` with every backslash turned into `/` (an empty list protects nothing); and, for any file inside the project, when a written **line** contains a dash character - em (U+2014), en (U+2013), figure (U+2012), horizontal bar (U+2015), hyphen (U+2010), non-breaking hyphen (U+2011), minus (U+2212), fullwidth (U+FF0D), two- and three-em (U+2E3A, U+2E3B), or the small and vertical forms (U+FE58, U+FE63, U+FE31, U+FE32). The one exception is a line that spells the punctuation rule itself (contains "plain hyphen"), and it is per line rather than per payload, so one exempt sentence cannot carry a whole file's dashes past the check. Files outside the project (memory, scratchpad) are not dash-checked. Delete the `DASH` check together with the Punctuation section of CLAUDE.md if the project does not want the rule.
- **The write fence.** When the payload names the agent, an `Edit` / `Write` or a mover target inside the project is refused outside that agent's paths (`FENCED_AGENTS`): `hunt` may touch only `<SRC_DIR>/__hunt_probe*.ts` - `node_modules` included. The fence narrows, it lifts nothing: a mover or redirect into an allowed path is still judged by every other check, and a delete still goes one path at a time. A project's own writer agent with a narrow job gets an entry of its own - an `allowed` regex over the project-relative path and the `what` its refusal names. A payload without `agent_type` fails open - the agent's prompt still carries the rule.

The deny list in `settings.json` stays as the first backstop: a deny outranks every allow at every scope, and it needs no script to run. It matches the raw command string, so it catches fewer shapes than the guard does - keep both. An allow or deny entry's `*` compiles to `.*` under the `s` flag, anchored at both ends (measured on Claude Code 2.1.296), so it spans spaces, slashes and extra arguments. The one path wildcard in the shipped allow list is the probe compile, `npx tsc -p * --noEmit --tsBuildInfoFile *`, which also approves a `--tsBuildInfoFile` or `--generateTrace` aimed into the project.

**Known gaps.** A bypass nobody would type by accident is recorded here, not closed with more guard code; a realistic slip, or a retry after a refusal, is a defect to fix.

- Refused though harmless (fail-closed): what the as-written view makes of a comment - a quoted string after a `# it's` comment read as a command, trailing comment words read as arguments (`rm <SRC_DIR>/a.ts # orphaned` counts two paths, `cp a b # backup`, `ls # then git add`), a `;`, `|` or `&` in a comment before a `cd` word; a `cd` line inside a heredoc body, behind an unquoted `cmd /c`, after a `;` in a backtick body, after a `case` pattern's `)` inside a subshell, or after a line continuation, a PowerShell hashtable key named `cd`, and `echo x | cd`; a mover target whose own name holds a comma; one path spelled relative and absolute in one call (two deletes); a copy or `find -maxdepth 1 -delete` into an ancestor directory of the project, and a glob or bracketed name directly under one; a `\\?\UNC\` path; a target held in a leading-literal variable not named as scratch, beside a sibling value holding shell syntax or a quoted `~`, a Bash-managed name, or a comment, heredoc or `eval` in the command (`U="...?a=1&b=2"; O=/tmp/o; curl "$U" -o "$O"`, `O=/tmp/o.txt; echo hi > "$O" # note` - name it `$S`); a `git grep` word that only looks like `-O` (`git grep -eOrder`, `-e "-O"`), a `--output` search pattern or path (`git log -S "--output"`), and `--output=<scratch path>`; search text holding `bash -c '...'` or `sh -c`; `[[ "$a" > "b" ]]`; a heredoc whose body mentions a banned form; `echo '$(git commit)'`; `printf` / `echo` text naming a git write verb; a `node -e` / `python -c` one-liner whose code quotes a git write verb as text.
- The stdin and arithmetic checks. Refused though harmless: a script an interpreter reads on stdin that writes to a computed path, scratch included (`os.path.join(os.environ['TEMP'], ...)` - write it to a scratch file and run it by path); a write API anywhere else in a command that also feeds an interpreter on stdin; an arithmetic command `(( n > 0 ))`, which Bash may also parse as nested subshells. Passes though it writes: a `$((` opened inside quotes, which blanks everything up to the next `))` from every check but the `cd` one; a stdin script fed in a shape the check does not read (`<<EOF node` with the redirect first, `node /dev/stdin`, `node <(...)`, `python -m code`, an interpreter flag whose value it does not know).
- Passes though it writes, for a fenced agent: whatever a process it starts writes, and a `Write` to an absolute path outside the project, such as another worktree.
- Passes though it writes, outside the JS formatters above: another stack's formatter (`gofmt -w`, `black`, `ruff --fix`, `cargo fmt` - add its form to `IN_PLACE_EDIT` for such a project) and a fixing package script (`npm run lint:fix`); git that writes files (`format-patch` without `--stdout`, `archive -o`, `bundle create`); a download into the cwd (`curl -O`, `wget` without `-O`); `ln`, `touch`, `tar -x -C`, `unzip -d`, `sed`'s `w` command, PowerShell's `Export-Csv`, `Expand-Archive` and `Start-Transcript`; a shell-out inside a one-liner (`execSync('rm ...')`, `os.system`, `subprocess`) and `perl -e` / `ruby -e` / `deno eval` writes; a git verb from a variable or substitution (`git $v`, `git $(echo commit)`); a `NotebookEdit`, which the matcher does not route here.
- Passes though it writes: a target spelled as any other variable plus a path holding `/tmp/`, `Temp` or `scratchpad` (`> $ROOT/<SRC_DIR>/Temp/x`) - only the listed scratch variables should pass, but the check reads the substring; a listed scratch name set to a project path by an assignment that is not a leading literal (`true; S=<SRC_DIR>; rm -r $S`, `S=$PWD/<SRC_DIR>; cp a "$S/x"`, and `A=$HOME; S=<SRC_DIR>; ...`, where the non-literal first assignment ends the leading scan), or rebound to one after a scratch leading value (`S=<scratch>; cp a "$S/x"; S=<SRC_DIR>; rm -r "$S"`); a quoted `~` path, which Bash keeps literal and writes as `./~/...` inside the project while the check reads a home path - `cp a "~/AppData/Local/Temp/x"`; a leading-literal name rebound by `coproc X`, `wait -p X`, `printf -v "X"` / `-vX`, or a shell-managed `DIRSTACK` / `COLUMNS`; a `~` after a space inside a quoted leading value (`X="/tmp/a ~/AppData/Local/Temp/x"; cp a $X`); `IFS` splitting a scratch value, which then passes by its name (`IFS=:; S="/tmp/a:<SRC_DIR>"; rm -r $S`); the substitution's quote tracking, which misreads a single quote inside `"$(...)"` and after an escaped backslash (`"\\"`).
- Passes though it writes: an `Edit` / `Write` of any path under a `.git`; a `cd` behind `eval`, `builtin`, a backslash or quotes (`\cd`, `"cd"`), PowerShell's `iex "cd ..."` or a module-qualified `Set-Location`; a git `-O` the read-git check never sees as one (`git grep $'-Ocat'`, a quoted git path with spaces, `xargs git grep -Ocat`); cmd switches glued to the verb (`cmd /c rd/s/q <dir>`); an escaped apostrophe in ANSI-C `$'...'` quoting, a `${` inside a heredoc body, a PowerShell here-string that holds a `"`, and a doubled PowerShell backtick before `#`; a command after a heredoc or PowerShell here-string whose body holds an odd number of apostrophes counted both with and without the ones after a `#` word; a comment glued to `(` or `$(` (`(# it's`), or behind an escaped backslash or a line continuation, whose apostrophe hides the lines after it; a `cd` after an escaped or heredoc `(` left unbalanced; a brace list that names two deletes in one token (`rm <root>{/a.ts,/b.ts}`); numeric `open` flags; `pathlib` writes; `case` patterns inside `$(...)`; `timeout` / `env -S` combinations beyond the common forms; a deliberate `--noEmit false` under the `npx tsc` allow entry; a git alias defined with `-c alias.` (`git -c alias.x=commit x`); a verb assembled by string concatenation for `Invoke-Expression`; a scratch variable climbing out with `..` (`$TMP/../../<SRC_DIR>`); a path spelled with a trailing dot, an 8.3 short name, the `\\.\` device prefix or an admin share; a bash brace range or list that the split at braces hides (`rm -rf /d/code/my-ap{o..q}`); an in-tree marker path behind a cwd spelling the check does not rewrite (`$PWD.Path/tmp/x`); `git -C ${ROOT} commit` (the braces split `-C` from its value); a verb assembled inside a one-liner (`'git ' + 'commit'`, `` `git ${v}` ``); git from a `perl -e` one-liner whose first git call is a read; `& git @('add','-A')` and `Start-Process git -ArgumentList @(...)`; `-i` after `sed`'s script (`sed 's,a,b,' -i f`) or after a flag holding a comma (`--expression=s,a,b,`, `perl -Mx=a,b -pi`).

**Self-test** after any change to the regexes, from the project root:

```bash
node .claude/hooks/tests/guard-test.mjs
node .claude/hooks/tests/guard-shell-test.mjs
```

Every line must read `ok`; the tests set `CLAUDE_PROJECT_DIR` themselves. The payloads are built in JavaScript on purpose - a Windows path or a dash typed into a shell argument gets mangled before the guard sees it. Add a case per `PROTECTED_PATHS` pattern (the two commented lines in `guard-test.mjs`).

## upkeep-nudge.mjs - the upkeep reminder

Reads the date in `.claude/.last-maintain` (gitignored, one `YYYY-MM-DD` line, written by `maintain-ai-layer` after a `weekly`, `deep` or `init` run) and, when it is 14 days old or more, more than a day ahead, missing or unreadable, injects a line telling the model to tell the user once that `/maintain-ai-layer` is due - never to start it. Silent in a linked worktree (the nearest `.git` is a file): the pass runs in the main tree, and a second tree would be told so on every session. It reports and never blocks. Self-test: `node .claude/hooks/tests/upkeep-nudge-test.mjs`.

## stop-check.mjs - the Stop hook

Runs `<CHECK_COMMAND>` (the `CHECK` constant at the top of the script, the one verification call from `CLAUDE.md`, run through the shell) at the end of a turn when the tree moved off the session's start state, and blocks the turn on a failure. One file, two events, both registered in the tracked `settings.json`, so nothing goes into `settings.local.json` and a new worktree has the hook once its `.claude` folder exists. The always-on summary lives in `CLAUDE.md` under `## Commands`.

- **`SessionStart`** (`startup`, `resume`, `clear`, `compact`; timeout 30) stores the current tree key as this session's baseline under `%LOCALAPPDATA%/claude-stop-check/` (or `$XDG_CACHE_HOME`, or `~/.cache`), keyed by the repo root and the session id - **only when that session has no baseline yet**. `/compact` and `resume` keep the session id and fire `SessionStart` again; re-baselining there would pass the session's own edits. `fork` is absent from the matcher: a fork's new id would baseline the parent's already-modified tree. State files untouched for 15 days are pruned at session start.
- **`Stop`** (timeout 180) exits at once when `stop_hook_active` is set. Otherwise it computes the tree key and skips the check only when the key is defined **and** equals the baseline, the key of the last passing run, or the key of the last failure it already blocked on. A missing baseline or an undefined key (any git error) counts as changed. The check gets 150 s; past that its whole process tree is killed (`taskkill /T` on Windows, the process group elsewhere), so no orphaned compiler keeps writing build info. Keep the registered timeout above that budget: a hook the harness kills writes nothing and leaves its checker running.

**The tree key** is `HEAD` plus every changed, untracked or deleted path with a hash of its content (`git status --porcelain -z --untracked-files=all`, run with `GIT_OPTIONAL_LOCKS=0` so it never takes `index.lock` from under the owner's own git command, and with `core.ignorecase=false` so a case-only rename shows as a change). A turn that edits nothing after a passing run costs nothing, and an edit reverted to the original reads as unchanged. Two kinds of path never count: the reviewer's compile probe `<SRC_DIR>/__hunt_probe*.ts`, which comes and goes while a review runs, and `.claude/sessions/`, which holds notes, not code.

**Output.** A single JSON object on stdout and exit 0, never a bare exit code - a hook that errors must report, never wedge the session (`guard.mjs` is the opposite: stderr and exit 2). A pass stores the key as the last passing one and prints nothing. A failure stores the key as the last blocked one and prints `{ "decision": "block", "reason": <the last 60 lines of the check's output> }`, the reason ending with: a failure in a file this task neither touched nor reaches is the owner's own edit or a parallel session's - say so instead of fixing it. A check that could not run or overran prints `{ "systemMessage": "... Nothing was verified." }` and does not block.

**A check command that outlasts 150 s** overruns on every Stop and verifies nothing there: point `CHECK` at a faster subset of it (type-check and lint, say) and leave the whole chain to lifecycle step 9.

**The key covers the whole tree, unattributed**, so the owner's IDE or a parallel session in the same tree can trigger a run in this session; that is why the block reason says the failure may not be this session's. Nothing else: no review tracking, no waivers, no browser reminder.

**The compile probe.** Exclude `<SRC_DIR>/__hunt_probe*.ts` from the build and lint configs as well (the compiler's `exclude`, the linter's ignore list), so a probe live while a turn ends or while the main thread runs the check cannot fail it - and the probe agent compiles through a project of its own (`hunt.md`), because a probe excluded from the repo's project is not compiled by the repo's command either.

### What it does not cover

- **Formatting** - a formatter run at commit time stays the only formatting gate.
- **Any tree but its own** - a session editing files in another worktree passes clean while that tree is broken, and a worktree carrying an older copy of these hooks behaves as that copy says.
- **Whether the change was reviewed** - the review ladder lives in `crosscheck`, and the reply names every agent the task ran, so a skipped review is visible there, not here.

## Testing a hook

Never the live hook with a live payload: a real `Stop` payload makes the Stop hook write state for the real session id and run the real check, and a real `PreToolUse` payload runs the guard against the real tree. Copy the hook into the scratchpad, write `payload.json` beside it with `Write`, and run it with every path it reads pointed into the scratchpad:

```bash
S="$TMP/hooktest"   # scratchpad, never the repo
mkdir -p "$S/app"
cp "$(git rev-parse --show-toplevel)/.claude/hooks/guard.mjs" "$S/guard.mjs"
CLAUDE_PROJECT_DIR="$S/app" LOCALAPPDATA="$S/cache" TMP="$S" TEMP="$S" \
  node "$S/guard.mjs" < "$S/payload.json"; echo "exit $?"
```

`CLAUDE_PROJECT_DIR` is the project root the guard resolves and `LOCALAPPDATA` holds the Stop hook's state, so both have to move or the run touches the real ones. The Stop hook ignores `CLAUDE_PROJECT_DIR` and takes its root from its own location, so copy `stop-check.mjs` to `$S/app/.claude/hooks/`, give `$S/app` a `.git` (`git init` there - a scratch repo, never the project's), and point its `CHECK` constant at a trivial command in the copy. For the guard the payload is the whole test - `{ "tool_name": "Bash", "cwd": "<app>", "tool_input": { "command": "git commit -m x" } }` - with exit 2 a block and exit 0 an allow. `Edit` / `Write` / `MultiEdit` take `file_path` plus `content` or `new_string`, and `agent_type` exercises the write fence.
