# hooks

Three hooks, all registered in `.claude/settings.json` beside the deny list - or in `.claude/settings.local.json` when a personal install sits beside a tracked team `settings.json`; "the settings file" below means whichever holds them: `guard.mjs` and `backend-guard.mjs` as `PreToolUse`, and `upkeep-nudge.mjs` (end of this file). A `PreToolUse` hook reads one JSON payload on stdin and exits 2 with the reason on stderr to block the call, 0 to allow it; `backend-guard.mjs` has a third answer, a question to the user (below). **A guard that cannot parse its input allows the call**: each is a backstop, never a security boundary. Node 18+, no dependencies - the hooks are Node scripts whatever language the service is written in.

Start Claude Code at the repository root. Started in a subfolder it does not read the root `.claude/settings.json`: no hook and no deny entry is live, though `CLAUDE.md` still loads. `/hooks` shows what is registered.

The deny list and `guard.mjs` back up `CLAUDE.md` "Version Control"; they are backstops, not the rule. That is why `CLAUDE.md` keeps one-liner grants (`python -c`, `node -e`) out of every allow list: an allowed one-liner can run any git verb in code neither backstop reads closely.

`guard.mjs` is the same code in every layer of this bootstrap and knows nothing about servers; `backend-guard.mjs` holds what a server codebase adds. Keep them apart: a new check about files and git goes into the first, one about data, secrets or the outside world into the second.

## guard.mjs - what it refuses

**Bash / PowerShell**

- A git verb that commits, stages, publishes or discards work - wherever a shell runs git, judged on the words it receives (a quoted `-C "D:/Work Projects/x"` is one word): at command position behind `git -C` or `git -c`, a wrapper, `npx` or a launcher (`xargs`, `find -exec`, `Start-Process`), inside `$(...)`, `cmd /c`, a `bash -c` / `iex` body, as a quoted full path to the binary; and anywhere inside code an interpreter runs (a `node -e` / `python -c` / `perl -e` one-liner, a script fed on stdin or piped into `bash`). Git words in an argument are text (`echo "never git push"`). `git stash` is judged by an allow list (`list`, `show` pass); `git send-email`, `subtree` writes, `lfs push` / `migrate` (not `lfs pull`) and a `fetch` into a local branch count too. A tool that commits or tags through git: `npm` / `pnpm` / `yarn version` (unless `--no-git-tag-version`), `release-it`, `standard-version`, `semantic-release`, `lerna version` / `publish`, `changeset publish`. A read git verb that runs a program or writes a file - `git grep -O<cmd>` / `--open-files-in-pager`, any verb's `--output=<file>` - which the read-only `git diff:*` / `git log:*` / `git show:*` allow entries would otherwise approve with no prompt. A `gh` call that writes.
- A write into the tree from the shell: an in-place edit (`sed -i`, `perl -i`, `ruby -i`, `yq -i`, `prettier --write`, `eslint --fix` and `stylelint --fix` however they are started, and other stacks' formatters - `black`, `isort`, `ruff format`, `gofmt -w`, `goimports -w`, `go fmt`, `golangci-lint run --fix`, `dotnet format`, `dotnet csharpier`, `cargo fmt` and the like, unless a check flag keeps them read-only; a project's own task such as `./gradlew spotlessApply` passes), sed's `w` command, a redirect, `Set-Content` / `Add-Content` / `Out-File` (or, in PowerShell, `sc` / `ac`) whose target is a project path, a copy or move whose destination is inside the project, an interpreter one-liner, or a script an interpreter reads on stdin (`python - <<'EOF'`), that opens a file for writing (pathlib's `write_text` included). sed's `e` command runs a shell and is always refused. A Bash variable a leading statement sets to a literal (`O="/tmp/out"; cp a "$O/b"`) is judged as that literal, and one set from `mktemp` (`T=$(mktemp); npm ls > $T`) or PowerShell's `New-TemporaryFile` as scratch; one the rest of the command may rebind stays unresolved and is refused. A heredoc body no shell reads (`cat > /tmp/x <<'EOF'`, `python3 - <<'EOF'`, `psql <<'SQL'`) is not judged as commands; one a shell reads is.
- A delete beyond the one grant: one non-recursive project path per call (cmd's `/s` counts as recursive, clustered as `/s/q` too), never a `PROTECTED_PATHS` match, `.git`, `.claude/hooks/**` or `.claude/settings*.json`.
- A `cd` outside a Bash subshell - the working directory persists across calls, so one `cd` retargets every later relative path. The refusal names the retry form for its shell.
- A mover, deleter or downloader named with its `.exe` / `.com` suffix or by its full path (`rm.exe`, `/usr/bin/rm`, `curl.exe`, `cmd.exe` by its path) is judged by its bare name; a relative path such as `./install` is a project script and keeps its name.
- Every command is judged twice, as written and with its shell comments blanked, so a `# it's` comment cannot hide a later line.

**Edit / Write / MultiEdit / NotebookEdit**

- A `file_path` matching `PROTECTED_PATHS` (top of `guard.mjs`; case-insensitive on Windows and macOS): the generated and externally owned files, filled at install (`INSTALL.md`). A placeholder left unfilled reads as an empty list and protects nothing, and a misfilled one is named in one stderr line and reads as empty too - the other checks still work.
- Any written line carrying an en dash (U+2013) or an em dash (U+2014) (`DASH`); every other dash-like character passes.
- Files outside the project are never checked: a scratchpad script or a memory file may contain anything.

The in-place formatters it refuses are the direct binaries (the JavaScript ones, `black`, `isort`, `ruff`, `gofmt`, `goimports -w`, `go fmt`, `golangci-lint run --fix`, `dotnet format`, `dotnet csharpier`, `cargo fmt`, `rustfmt`, `ktlint -F`, `google-java-format -i`, `clang-format -i`, `rubocop -a`). A build tool's formatting task (`./gradlew spotlessApply`, `mvn spotless:apply`) is the project's own script and passes - `CLAUDE.md` Code Style says who runs the formatter. A formatter this project runs that is not on the list: add its form to `formatterWrites` in `guard.mjs`, with a case in `tests/guard-shell-test.mjs`.

**Refused though harmless - known.** `guard.mjs` fails closed: where it cannot tell a harmless command from a banned one, it refuses. The cases below are known, not defects to report, and each has a way round.

- **A shell comment in the command**: a quoted string after a `# it's` comment is read as a command, trailing comment words as arguments (`rm old.py # orphaned` counts two paths, `cp a b # backup` copies onto `backup`), and a `;`, `|` or `&` in a comment before a `cd` word as a `cd`. Drop the comment and say it in the reply.
- **A `cd` word the guard cannot place**: a `cd` line inside a heredoc body a shell reads, behind an unquoted `cmd /c`, after a `;` in a backtick body, after a `case` pattern's `)` inside a subshell or after a line continuation; a PowerShell hashtable key named `cd`; `echo x | cd`. Use absolute paths or a Bash subshell, `(cd dir && cmd)`; rename the key.
- **Paths**: a move target whose own name holds a comma; one path spelled relative and absolute in one call, read as two deletes; a copy or a `find -maxdepth 1 -delete` into a folder above the project, and a glob, or a bracketed name that does not exist as written, directly under one; a `\\?\UNC\` path. Spell a path once, in one form; a step in a folder above the project is the owner's to run.
- **A target held in a variable**: a variable a leading statement sets to a literal and that is not named as scratch, beside a sibling value holding shell syntax or a quoted `~`, a Bash-managed name, or a comment, heredoc or `eval` in the command (`U="...?a=1&b=2"; O=/tmp/o; curl "$U" -o "$O"`, `O=/tmp/o.txt; echo hi > "$O" # note`). Name the scratch variable `$S`, or write the path out.
- **Text that only looks like a banned form**: a `git grep` word that looks like `-O` (`git grep -eOrder`, `-e "-O"`), a `--output` search pattern or path (`git log -S "--output"`) and `--output=<scratch path>`; search text holding `bash -c '...'` or `sh -c`; `[[ "$a" > "b" ]]`; a heredoc whose body a shell reads, or an unquoted one whose `$(...)` or backticks name a banned form; a `node -e` / `python -c` / `perl -e` one-liner, or a script fed to an interpreter on stdin, whose code quotes a git write verb as text; a `node` / `python` call with `-e`, `-r` or `-c` among its script's arguments that quotes one. Search with the Grep tool; put the code in a scratch file and run it by path.
- **A script on stdin, and arithmetic**: a script an interpreter reads on stdin that writes to a computed path, scratch included (`os.path.join(os.environ['TEMP'], ...)`); a write API or a git write verb anywhere else in a command that also feeds an interpreter or a shell on stdin; an arithmetic command `(( n > 0 ))`, which Bash may also parse as nested subshells. Write the script to a scratch file and run it by path; test with `[ "$n" -gt 0 ]`.

**Passes though it writes - known gaps.** The guard reads the text of one call, so a bypass nobody would type by accident is recorded here rather than closed with more guard code; a realistic slip, or a retry after a refusal, that passes is a defect to fix in `guard.mjs`. The self-tests pin two of them as `(allow, known gap)`.

- **Whatever a process the command starts writes**: a script file run by path, a package or task-runner script (a `format` script, `make fmt`, `./gradlew spotlessApply`), a build tool, a formatter missing from `formatterWrites`, a shell-out inside a one-liner (`execSync('rm ...')`, `os.system`, `subprocess`).
- **Writes no check lists**: a download into the working folder (`curl -O`, `wget` without `-O`), `ln`, `touch`, an archive unpacked into the tree (`tar -x -C`, `unzip -d`), git that writes a file (`format-patch` without `--stdout`, `archive -o`, `bundle create`), a release tool missing from `RELEASE_TOOL`.
- **A verb or a path the call builds at run time**: `git $v`, `git $(echo commit)`, an alias defined in the call (`git -c alias.co=commit co`), a verb concatenated for `Invoke-Expression`; a scratch variable climbing out with `..` (`$TMP/../../app/a.ts`); a quoted `~` path, which Bash keeps literal and writes inside the project.
- **A `cd` the guard cannot see as one**: behind `eval`, `builtin`, a backslash or quotes (`\cd`, `"cd"`), PowerShell's `iex "cd ..."`.
- **An `Edit` / `Write` of a path under `.git`.**

## backend-guard.mjs - what it refuses, and what it asks about

It answers a call in one of three ways: it allows it, it refuses it (exit 2), or it **asks the user** - it prints a `permissionDecision` of `ask`, and the user sees a permission prompt with the reason. A refusal anywhere in a call outranks a question.

**Secret files - refused.** An env file (`.env`, `.env.local`, `.env-production`, `prod.env`, `.envrc`), a private key or keystore, an ssh key, cloud, registry and git credentials, a `secrets` or `credentials` file, a service-account key, terraform state and `terraform.tfvars`, Maven's `settings.xml` / `settings-security.xml`, the home `~/.gradle/gradle.properties`, the home `.npmrc` / `.yarnrc.yml` / `NuGet.Config` (a project's own stays readable), kubeconfig files, gcloud credentials and `client_secret*.json` - plus the project's own list (`SECRET_RAW`). What stays readable: a name that says it is an example (`.env.example`, `.env.local.example`, `.env.sample`, `.env.template`, `.env.dist`, `example.env`), a `.pem` or `.key` whose name says it is public (`ca.pem`, `jwt_public.pem`, `fullchain.pem`), a `.pub` key, `known_hosts`, and a `secrets.yaml` under a chart's `templates/`. An env file with no secret in it that the project tracks on purpose (`.env.test`) is still refused until its built-in pattern in `SECRET_PATHS` (not the project list `SECRET_RAW`) is narrowed.

- `Read` of one, `Grep` with one as its `path` or `glob` (a wildcard or a brace that spells its name counts: `.env*`), and `Edit` / `Write` / `MultiEdit` of one - inside the project or outside it.
- A shell command that prints or copies one: a reader (`cat`, `head`, `grep`, `sed`, `Get-Content`, `tar`, `cp`, ...) with the file or a glob that spells the name (`.env*`, `*.env`) after it, at any depth - inside `$(...)`, a `bash -c` body, a `find -exec` - and `git show` / `git diff` / `git log -p` of one. A searcher's pattern, an `--exclude` and a copy's destination are not reads: `grep "\.env" app`, `rsync --exclude .env`, `cp .env.example .env` (which `guard.mjs` refuses for its own reason, as a shell write into the tree). `< file` on stdin counts. So does an interpreter one-liner or a .NET file call whose string names one: `node -e "...readFileSync('.env')"`, `python -c "open('.env')"`, `[IO.File]::ReadAllText('.env')`. An archive, a recoding or a Windows copier copies one too (`zip`, `Compress-Archive`, `gzip`, `iconv`, `perl -pe`, `certutil -encode`, `openssl base64`, `robocopy`, `xcopy`; a copy whose target an option names, `cp -t /tmp .env`, `Copy-Item -Destination x -Path .env`), and so does an upload of one - a value spelled `@file` or `<file` (`curl -F "f=@.env;type=text/plain"`, `--data-binary @.env`), the value of `-T`, `--upload-file` or `-InFile`, a `-Form` entry; a hash (`certutil -hashfile`), a key generation (`openssl genrsa -out`), `zip -x .env`, a client certificate (`curl --cert x.pem --key x.key`) and a URL path do not. **A copy or archive of a whole folder** is walked like a search, past its own exclusions: `tar -czf b.tgz .`, `zip -r b.zip .`, `Compress-Archive -Path config`, `Copy-Item -Recurse config x`, `cp -r . /tmp/bk`, `robocopy . x /E` are refused with a secret file in the folder; `tar --exclude=.env`, zip's `-x` and robocopy's `/XF` keep one out. A path is also judged as it resolves from the call's folder, so a project entry such as `config/local\.settings\.json$` holds for `cat local.settings.json` run inside `config`; and by the name Windows opens - a trailing dot or blank and a stream suffix (`.env.`, `'.env '`, `.env::$DATA`) are the file itself.
- **A wildcard that takes one on disk**: the folder a reader's wildcard names is listed, and a secret file among the names it matches is refused - `cat .e*`, `cat .[e]nv`, `gc .en*`, `Get-Content *`. Under Bash a wildcard that opens the name skips dot files (`cat *` passes in a folder whose only secret is `.env`), as the shell does; PowerShell's does not. A wildcard after an option that takes a filter or a pattern (`rg -g '*.json'`, `find -name`, `--include`) is never expanded.
- **Names piped into a reader**: a PowerShell listing or item piped into a cmdlet that reads each file (`Get-Item .env | Get-Content`, `gci -Filter .env* | gc`, `gci | gc` - no operand is the folder itself; `gi .env | % { gc $_ }` too), and under xargs the names `echo` prints or the files `ls` lists (`echo .env | xargs cat`; `ls` without `-a` hands on no dot file). Under Bash `ls | cat` only prints the names and passes; so does a listing piped into anything that does not read files (`gci | Sort-Object Name`).
- **A delete or move of one** - by name, by a wildcard that takes one, behind a deleting `find` (`find . -name .env -delete`), or piped into a remover (`echo .env | xargs rm`, `Get-Item .env | Remove-Item`): a secret file holds values only the owner has. A move's destination is not removed (`mv .env.example .env` passes), a filter's value is not either (`Remove-Item app\* -Exclude .env`), and `git rm --cached .env` only stops tracking it. A deleting walk over a tree too large to check is asked about, as a search is.
- **A search that reads a whole folder with one in it, at any depth**. The hook walks the folders the command names (none: the current one) and refuses when a secret file is among the files the command would read:
  - a recursive `grep` (`grep -rn KEY .`, `grep -rn KEY apps` over `apps/api/.env`);
  - `rg` told to read ignored or hidden files (`-u`, `-uu`, `--no-ignore`, `--hidden`) - judged as a search of every file;
  - `findstr /s`, and a wildcard handed to `findstr` or `Select-String` (`Select-String -Path * -Pattern KEY`), which reads the matching files of that one folder;
  - a file listing piped into `Select-String` (`Get-ChildItem -Recurse | Select-String KEY`, `gci -r | sls KEY`; without `-Recurse`, the folder's own files);
  - a `find` that hands its files to a reader (`find . -type f | xargs grep KEY`, `find . -type f -exec grep KEY {} +`).

  The walk skips `node_modules` and `.git`, which a search almost never means; build output (`build`, `dist`, `target`, ...) it walks, as grep does, unless the command's own `--exclude-dir` names it. What passes: plain `rg`, which honours the ignore files and skips hidden ones; `git grep` and the Grep tool over files git ignores (next bullet for the ones it does not); a search in a folder that holds no secret; and a filter that keeps every secret out - `--exclude` / `--exclude-dir` / `--include`, `rg -g` or `-t`, `-Include` / `-Filter` / `-Exclude`, find's `-name` and `-maxdepth`, a wildcard no secret's name matches (`*.py`), a listing of names only (`-Name`). **Past 20 000 entries the tree is too large to check, and the user is asked.**
- **A search that prints the lines of a secret file git does not ignore** - one it tracks (a config file on the project list, say), or with `--untracked` one it merely does not ignore: the Grep tool with `output_mode: content`, and `git grep` without `-l` / `-L` / `-c` / `-q`. Git lists the files under the path or the pathspecs; a folder git ignores itself, which the Grep tool still reads when named as its path, is walked instead - a worktree's root never counts as one. What passes: a list of file names (`files_with_matches`, `git grep -l`), a Grep `glob` or `type` and a pathspec that leave the file out (`-- '*.java'`, `':!config/app-prod.yml'`, a `glob` of `!.env*`); a `glob` with a slash is matched against the path, one without against the file name, and a `glob` list (`*.py,*.json`, `*.yaml *.yml`) is read entry by entry. A keystore (`.jks`, `.p12`, `.pfx`) is binary and is printed by neither search, so it does not count here - unless `git grep -a` reads it as text. The secret lists are tested against the whole path wherever the search starts. A revision handed to `git grep` (`git grep KEY HEAD`) is not looked into.
- `docker compose config` (and its alias `convert`), which prints the file with every env value filled in - unless `--services` / `--volumes` / `--profiles` / `--images` / `--networks` / `--hash` / `-q` makes it print names only, or every `--env-file` is an example file.
- Loading one into a process prints nothing and passes: `. ./.env`, `docker compose --env-file .env`.

**Frozen files - refused.** A path matching the frozen list (`FROZEN_RAW`: the migration files; case-insensitive on Windows and macOS) that is on the upstream default branch as of the last `git fetch` - the hook never fetches (`origin/HEAD`, else `origin/main`, else `origin/master`); with no such ref - no remote, or a repo made with `git init` whose default branch has another name, where `git remote set-head origin --auto` creates it - one git tracks:

- `Edit` / `Write` / `MultiEdit` of it, and a shell delete or move of it, of its folder or of a glob that reaches it. A migration the task itself created is not tracked yet and stays editable, and a new file in the folder is always allowed.
- A delete or move is judged where the command itself removes: a remover at its head (`rm`, `mv`, `Remove-Item`, `del`, ..., behind `sudo` or `xargs` too), `git rm` / `git mv`, `find -delete` and `find -exec rm` over the folders they start from, and `cmd /c del`. A remover word that is another tool's verb, with a name after it, is not one: `docker rm -f db`, `docker compose rm -sf db`, `npm rm db` (`docker volume rm` is asked about, as data).
- A migration committed only on the working branch stays editable: it is still the developer's to fix before the merge.

**Commands that leave the machine - refused.** One built-in list (`FORBIDDEN`), plus the project's own (`FORBIDDEN_RAW`):

- **deploy and infrastructure**: `kubectl` and `helm` verbs that change a cluster (the refusal names the local retry: `--context kind-<name>` for `kubectl`, `--kube-context` for `helm`), `terraform` / `pulumi` apply and destroy, `ansible-playbook` without `--check`, the write verbs of the cloud CLIs `aws`, `gcloud`, `az`, `gsutil` and `azcopy` (what creates, changes, deletes, runs, scales, swaps or publishes, an upload to a bucket and a copy from one bucket to another included; a download, a `list` / `describe` / `show` / `get-*` and `aws configure` / `gcloud config` / `az account` pass), `az acr build|run`, `skaffold run|dev|deploy|delete` without a local `--kube-context` (it deploys to the current context; the refusal names the retry), `dotnet publish|build|msbuild` and `msbuild` with a `PublishProfile=`, `WebPublishMethod=` or `DeployOnBuild=true` unless a folder profile, the deploys of the common deploy and hosting tools, and a docker call that changes another host (`-H`, `--context`, `DOCKER_HOST` or `DOCKER_CONTEXT` naming one, on the call or assigned earlier in the same command with `export` / `$env:`; `ps`, `logs` and the other reads pass).
- **publish**: an image push (`docker`/`podman` push or a `--push` build, Gradle `jib`, Maven `jib:build`, `bootBuildImage --publishImage`, `spring-boot:build-image` with publish on, `ko build|apply|resolve` without `--local`, `crane push|copy|delete|tag|mutate|append|rebase`, `buildah push` and `buildah manifest push`, `skopeo copy|sync|delete` to a registry that is not local, `oras push|attach|cp`), a package publish (npm, PyPI, crates, gems, Maven, Gradle, sbt, NuGet, Hex), a release.
- **What passes**: a command carrying `--dry-run`, and a command aimed at this machine by its own words - `--endpoint-url` on localhost (an emulator), the `gcloud` emulators, `--context` naming a local cluster (`kind-*`, `k3d-*`, `minikube`, `docker-desktop`) and `kubectl config use-context` switching to one, an `azcopy` target on localhost, an image push to a registry on localhost, a `--push` build whose every tag is on localhost, a jib build whose `-Dimage=` / `-Djib.to.image=` is on localhost, a folder publish profile, `jibDockerBuild` / `jib:dockerBuild`. A `kubectl apply` that names no context is not known to be local and is refused.
- The lists are closed: a deploy tool or a cloud verb they do not name, and a task-runner target that wraps one, go into the project's forbidden list.

**Commands that destroy data - the user is asked.** `docker compose down -v`, a volume or system prune, `DROP` / `TRUNCATE` / a `DELETE` or `UPDATE` with no `WHERE` handed to a database client (`-c`, a pipe from `echo` or, in PowerShell, from a quoted string, a heredoc), a cache flush, and the migration tools' wipe commands (`migrate reset`, `migrate:fresh`, `db:reset`, `flush`, `downgrade base`, `database drop`, `database update 0`, `down -all`, `clean`), a rollback past one step or to a target the hook cannot size (`alembic downgrade -2` or to a revision, `db:rollback STEP=3`, `db:migrate VERSION=...`, `manage.py migrate <app> <migration>`, `dotnet ef database update <migration>`, golang-migrate's bare `down`, `goose down-to`, `ecto.rollback --step 3`, a liquibase rollback past one changeset - the CLI's or the Maven / Gradle plugin's (`mvn liquibase:rollback -Dliquibase.rollbackCount=3`, `gradlew rollbackCount`) - `db:migrate:undo --to`, golang-migrate's `goto`), and a delete or move of a database's data folder, outside the project too (`/var/lib/postgresql/...`, a `pgdata` bind mount, `/data/db`, `"$PGDATA"`). A step back by one migration passes with no question - the edit-and-retry loop on the task's own migration - and a redirection is never read as a target (`dotnet ef database update 2>&1 | tail`, `migrate orders > migrate.log`). `migrate` as a package script (`npm run migrate down`) or a compose profile is not golang-migrate. **Rewriting the migration history is asked about too**: `alembic stamp` / `flask db stamp`, `manage.py migrate --fake`, `flyway repair` (and `flywayRepair`), golang-migrate's `force`, `liquibase changelog-sync` and `clear-checksums` (the plugins' `changelogSync` and `clearCheckSums` too), `dotnet ef migrations remove`, `prisma migrate resolve`. **Asked as well**: `kubectl get secret` with an output that prints the values (`-o yaml|json|jsonpath|go-template|custom-columns`; a plain list of names and `describe`, which shows byte counts, pass), a read from a cloud secret store that prints the value (`aws secretsmanager get-secret-value`, `aws ssm get-parameter` / `get-parameters` with `--with-decryption`, `gcloud secrets versions access`, `az keyvault secret show`, `heroku config` and `config:get`; a list of names, a `describe` and a parameter read with no decryption pass), a secret a tool keeps or decrypts (`dotnet user-secrets list`, `rails credentials:show`, `sops -d`, `vault kv get` / `vault read`, `op read` / `op item get`), `ssh` / `scp` / `sftp` / `rsync` to a host that is not this machine (`ssh -T git@<host>`, a key check, passes), a tunnel to a database elsewhere (`kubectl port-forward` without a local `--context`, `cloud-sql-proxy` - behind `nohup` or `sudo`, by its release asset's name or as a `docker run` image too - `gcloud sql connect`, `gcloud compute start-iap-tunnel`, `az postgres|mysql ... connect|execute`, `heroku pg:psql`, `fly proxy`, `railway connect` - after a port-forward, `localhost` is that database), a database client or dump tool whose own words name another host (`psql`, `mysql`, `pg_dump`, `mysqldump`, `mongodump`, `mongoexport`, `redis-cli`, ... with `-h` / `--host`, sqlcmd's `-S`, a database connection URL, a libpq connection string (`psql "host=... dbname=..."`), a `PGHOST=` or URL assignment before it or earlier in the same call (`export`, `$env:`); one run inside a container passes - `docker exec`, compose, `kubectl exec` on a local cluster, a `docker run` on a network it names - while a `docker run` of a client image on no network asks), and a search over a tree too large to check. A host the hook cannot tell is this machine asks as well: a service name typed outside a container runner (`psql -h db` from a shell inside a dev container), a variable (`-h $DB_HOST`). The prompt is the owner's "yes, I asked for exactly that" - and with nobody to answer it (a headless run), the call is refused. Neither `--dry-run` nor a local endpoint skips the question.

**What is not judged.** A segment whose head only searches or prints (`grep`, `echo`, `git`, `cat`, ...), so `grep -n "terraform apply" README.md` is a search; a quoted argument with spaces in it, which is a message, a filter or a name (`-m "drop unused column"`, `-k "publish and not slow"`) unless a shell runs it; a heredoc body, or a PowerShell here-string, unless a shell (`bash`, `iex`, `Invoke-Expression`, `pwsh`) or a database client reads it - an apostrophe inside a here-string hides nothing after it, and a `<<` inside quotes opens no heredoc. A block or a keyword around a command is not a command of its own: `{ rm .env; }`, `& { ... }`, `1 | % { ... }`, `if ...; then ...` are judged by the command inside. A glob is matched without a regex, so a long or unbalanced one (`--include=[`) can neither time the hook out nor stop it.

**What it cannot see** - it reads the text of the call, so it misses a script file that runs the same command, SQL in a file handed to a client (`-f wipe.sql`), a secret printed from the process environment (`printenv`), a secret reached through a variable, a loop or a subexpression (`$p = '.env'; gc $p`, `Get-Content (Join-Path . '.env')`), a chain of more than one pipe (`ls -a | grep env | xargs cat`), a here-string assigned to a variable and used later, a shell nested more than three deep (or a delete inside a launcher's argument list, `Start-Process pwsh -ArgumentList '-c Remove-Item .env'`), a search fed from a list the hook does not read (`git ls-files -o | xargs grep`, a `find` with a `-path` or `-regex` test, a listing filtered through `Where-Object`), a tool that parses a key (`openssl rsa -in ... -text`), and a request sent to a shared host. It reads a database host only from the command's own words: one a client takes from its environment, an env file or a config file it cannot see. Those are `CLAUDE.md` "Data, secrets and the outside world".

## The project lists

`PROTECTED_PATHS` in `guard.mjs`, and `FROZEN_RAW`, `SECRET_RAW` and `FORBIDDEN_RAW` in `backend-guard.mjs`: each a JSON array of regex sources inside a raw string, filled at install, with a regex backslash doubled once as in a `.json` file. An unfilled or empty one reads as an empty list. **The path lists are tested against the absolute path with forward slashes, so an entry matches the path's tail and never starts with `^`** (`"db/migrations/[^/]+\\.sql$"`); a frozen entry names the numbered files only, never a file a new migration has to edit - a master changelog, an include list, a repeatable script - and matches whatever the case on Windows and macOS, as the secret list does everywhere. The forbidden list is tested against one command segment with its words joined by single spaces (`"\\bmake\\s+deploy(?!\\S)"`; a `\\b` after the target would refuse `make deploy-docs` too) and always refuses - a dry run does not pass it. A misfilled list - broken JSON, not an array of strings, a regex that does not compile - is named on stderr and only that list goes empty, in both hooks; every other check stays live. `backend-guard.mjs` also tells the user on every call (`systemMessage`), since stderr on an allowed call reaches nobody. Run the self-tests after every edit.

## Self-test

```bash
node .claude/hooks/tests/guard-test.mjs && node .claude/hooks/tests/guard-shell-test.mjs && node .claude/hooks/tests/backend-guard-test.mjs
```

Every case line must read `ok`, and each suite ends with `N passed, 0 failed`. **The guard shell suite needs the source-directory placeholder filled first** (the install does it): it builds its paths from that value, and an unfilled `<...>` reads as a redirect, so an unfilled copy fails the cases built from it, with nothing wrong with them. `guard-test.mjs` is meaningful from the first minute: its only placeholder paths are the fence cases, and the unfilled guard carries the same placeholder, so they still match. Once the source directory is filled in `guard.mjs`, it is filled in those cases too, or the probe case fails. It also tests the matching itself, case folding and a misfilled list on two temp copies of the guard with a known list.

`backend-guard-test.mjs` runs in four parts: the built-in checks against the installed hook, the three project lists against a copy of the hook with sample values in a throwaway git repo in the temp directory (the frozen cases make commits and remote refs of their own there, never in this tree), the same copy with the lists unfilled, and that copy started with `--harness codex` - `backend-guard.mjs`, like `guard.mjs`, also reads another harness's payloads behind that flag, where every question is a refusal, a misfilled list refuses every call and an interactive database client is refused; nothing in this layer starts it that way. A case expects `0` (allowed, nothing printed), `2` (refused) or `'ask'` (the user is prompted); a part-4 case `deny` or `allow`. It needs `git` on the path.

Add one case per entry of each project list - `guard-test.mjs` carries two commented lines showing the shape, `backend-guard-test.mjs` two more at the end of its first part. Run the suites after every change to a hook or to a list. A regex that does not compile takes the whole hook down, and a hook that crashes lets every call through. Each of the two `guard` suites ends with a block for `--harness codex`: `guard.mjs` also reads another harness's payloads behind that flag. Nothing in this layer starts it that way, and without the flag its behaviour is unchanged; the block keeps an edit to a shared check from breaking that form unseen.

## Switching a rule off

A rule is a section of the layer's `CLAUDE.md` (root, or inside `.claude/` in a personal install) plus its checks. Switch off all of them together, or the rule half-holds and the agent argues with it.

- **The commit ban**: every `Bash(git ...)` and `PowerShell(git ...)` entry of `permissions.deny` in the settings file; the `gitWrites(...)`, `gitWritesAnywhere(...)`, `releaseWrites(...)` and `ghWrites(...)` checks in `checkCommand` in `guard.mjs` (the `GIT_WRITE_VERBS` / `GIT_WRITE_SUBCOMMANDS` / `RELEASE_TOOL` lists they read can stay); the "Never Commit or Push" section of `CLAUDE.md`; and the suite cases that expect the refusal - the git, release-tool and `gh` cases marked `(deny)` in `tests/guard-shell-test.mjs` and the `git commit` case in `tests/guard-test.mjs`. **With the ban gone the frozen check loses part of its footing** - with no remote it trusts that only the owner commits - so narrow it or drop it too.
- **The `cd` rule**: the `checkChdir(...)` call at the bottom of `guard.mjs`, the "Never `cd`" bullet of `CLAUDE.md` "Shell and file edits", and the `cd` sentence in the Boundaries of `.claude/agents/hunt.md` and `drift.md`.
- **One backend check**: empty its project list and delete its entries from `SECRET_PATHS` or `FORBIDDEN` (a `RegExp` line each in `SECRET_PATHS`, a `rule(...)` line each in `FORBIDDEN`), the matching bullet of `CLAUDE.md` "Data, secrets and the outside world", and the cases in `tests/backend-guard-test.mjs` that expect its refusal or its question. To let a file the list calls secret be read (a tracked `.env.test`, a fixture key), narrow that one pattern. To stop the question on data commands, delete the `data` rules; to make them refusals instead, change the `ask(...)` calls into `deny(...)` in both `checkSegment` (the `data` kind; `reveal` and `remote` ask there too) and `checkStdinSql`. A project that deploys from the agent's session on purpose deletes the `deploy` rules it uses, not the kind.
- **A whole hook**: remove its `PreToolUse` block from the settings file. Without `guard.mjs` what remains is the deny list, which matches the **raw command string** only: `git -C <path> commit`, a quoted full path to the binary and a git call inside an interpreter one-liner all walk past it, and nothing at all is left against shell writes into the tree.
- **The hyphen rule has no off-switch**: the `DASH` check and the `Punctuation` section of `CLAUDE.md` stay in every install.

A new rule goes in with a test case in the same change. Both guards are regex over shell text: a rule with no test is a rule that works until the first quoted path.

## upkeep-nudge.mjs - the upkeep reminder

Registered as `SessionStart` (startup, clear). Reads the date in `.claude/.last-maintain` (committed with the layer in team mode, per machine in a personal mode; one `YYYY-MM-DD` line, written by `maintain-ai-layer`'s `deep` and `init` runs) and, when it is 30 days old or more, more than a day ahead, missing or unreadable, hands the model a line telling it to tell the user once that `/maintain-ai-layer` is due - never to start it. With no argument that runs `deep`, the monthly pass. Silent in a linked worktree (the nearest `.git` is a file), since the pass runs in the main tree. It reports and never blocks, and costs tokens only on the day it speaks. Self-test: `node .claude/hooks/tests/upkeep-nudge-test.mjs`, each case line `ok` and `N passed, 0 failed` at the end.
